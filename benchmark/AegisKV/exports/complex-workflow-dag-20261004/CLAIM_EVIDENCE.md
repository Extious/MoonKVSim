# Workflow 典型性：claim、来源与验证

核查日期：2026-10-04。此记录使用公开一手资料及当前设计约束，没有使用本仓库旧实验。图已简化为 Agent 和依赖边；没有改变论文、执行应用或采集新 trace。

## 当前可以支持的表述

> We design two document-centric multi-agent workflows—research-paper review and multi-source news synthesis—that instantiate common collaboration patterns, including parallel analysis, evidence integration, and staged verification.

中文：我们设计了论文审阅与多源新闻综合两个文档型多 Agent workflow，实例化并行分析、证据整合和阶段性核查等常见协作模式。

这里的“常见”限定在协作模式层面，由下列来源及图中的具体输入输出关系支持。具体角色数、依赖边和无工具连续多轮的组合是本项目设计，不能据此写成“两个 DAG 已被证明是典型生产 workflow”或“代表所有多 Agent 应用”。复杂程度与典型性是不同问题；单个 fan-out/fan-in 仍应保留为公开模式参照与简单结构基线。

## 如何建立可写入 Evaluation 的代表性

先把目标总体写清楚：固定 Agent 任务依赖、输入材料已就绪的文档型协作应用。若论文只研究这个范围，可以在该范围内验证代表性；不能在采集后仅保留满足“多轮、长历史、正 Slack”的任务，再宣称它们代表更广的应用总体。

1. **冻结应用及适配记录。** 固定角色、每条边的材料 schema、提示模板、停止条件和工具策略；逐项说明相对公开应用/任务的改动。自然一次调用即完成的角色也必须如实记录，不能额外增加调用使其满足预设多轮形态。
2. **验证分工必要性与输出。** 对新增角色/核查阶段做质量核验及必要的删除或合并比较，检查事实支持、覆盖、遗漏、冲突与最终可用性。新增角色若无可解释作用，应简化 DAG，而非保留其制造 Slack。
3. **采集不依赖 AegisKV 收益的参考运行。** 对真实任务的预先冻结样本记录实际角色调用次数、完整 token 历史、工具和本地开销、队列与服务区间、worker 身份及最终输出；保存失败、单轮、短历史和零重叠任务。停止/排除规则先于查看恢复结果。
4. **报告分布和适配差异。** 报告每类应用的 Agent 数、依赖深度/并行宽度、调用次数、历史增长、真实 KV 与工具占比；对原样公开方案可以采集的部分单独比较。多输入样本套入一个固定 DAG 只能体现输入多样性，不能建立拓扑的总体分布。
5. **选择图例与冻结性能实验。** 从非故障参考集按上述结构/执行特征选出公开规则下的展示 workflow，再固定 ID；不按大 Slack 或恢复收益挑图。典型性在选定应用类别内成立到什么程度，应由参考分布、质量及适配报告决定。
