# SlackLandlord：H/L 租值键与请求入口核对

2026-09-09。[流程 PDF](algorithm-2-rental-management.drawio.pdf) · [可编辑源](algorithm-2-patent-revised.drawio) · [公式说明](README.md)

本版入口明确为 **Agent a 的请求到来，决策其中一个完整 KV chunk x**。在保留独立 Agent 收益和单份额续租的基础上，以 H/L 代替逐轮显式扣账。20 个执行节点、24 条控制连线；增加了一个按需结算步骤，未恢复联合 WCT 或跨 Agent 收益分配。

## 关键逻辑

| 检查项 | 当前流程 |
|---|---|
| 新请求与逐块产生 | 完整块按前缀顺序处理，新生成块封闭后进入；没有未知未来 KV |
| 去重、过期、进行中操作 | 先等待进行中操作，再去重/检查过期；重复请求不补满信用 |
| 独立估值 | 只计算本请求 Agent 的 G_a,x |
| 旧租金与新授信分开 | ③按 H−L 比例结算，④只覆盖 a 的份额；其他 Agent 保留租后余额 |
| 持续在 Q 中的块 | L 推进时 H 不变，不扫描分账 |
| 离开和重入 Q | 退出先结算冻结；重入按当前 L 与冻结份额重建 H |
| 新候选 | H_x 在试算中固定；H_y≥H_x 拒绝，含同值 |
| 临时租金 | L′仅存在于临时状态；整次试算失败不改实际 L 或账本 |
| 空闲容量 | 可直接准入零信用块 |
| 复制与发布 | 提交时冻结候选租后余额；复制不收租；发布按当前 L 重建 H，不补满 |
| 冲突和执行失败 | 执行前核验 L/Q 等版本；执行后不回滚已发生的推进与释放 |

## 设计算术核对

[SEMANTIC_AUDIT.json](SEMANTIC_AUDIT.json) 有 **26 组检查**。保留前版 17 组独立 Agent、去重、共享分摊、零信用、多次回收、失败隔离、保护和事件顺序核对；增加 9 组 H/L 检查：

1. 推进 L 后延迟结算与逐份额比例扣租一致。
2. A 续租保留 B 租后余额；重复和旧请求不改键，新收益下降可下调 H。
3. Q 退出冻结、重入建键，不补扣暂停期间的租金。
4. 零分母安全、零余额首次正收益续租。
5. 多次回收中原有活跃 H 和候选 H 固定。
6. 新暴露尾块只从入队时开始付租。
7. 复制期间 L 增长不扣候选，发布重新基准化且不返还已付租金。
8. **12288 个精确对照案例**：不同字节数、分账、候选价值、初始 L、前缀和保护组合；H/L 与直接扣租的准入结果、回收顺序及全部保留余额一致。
9. 空闲容量接受零信用候选且不推进 L。

另保留 **2040 个单 Agent Slack 恒等式组合**。这些是有限模型的精确分数运算，非实验次数、性能样本或一般正确性证明。H/L 核对模型与直接扣租参考实现分别实现，不由同一比较函数互相调用。
