## 设计检查

[图结构检查](DESIGN_CHECKS.json)核对：只有一张决策页；已有备份无需经过尾块资格判断即可续租；新备份必须先经过准入与复制；分账与收益公式分开；没有 Agent 结束、解除引用、待兑现轮次、Lazy Refresh 或 H/L 状态；失败计划不污染真实账本。

[精确核算](SEMANTIC_AUDIT.json)包含以下 9 组检查，使用示意恢复代价与有理数运算，不是物理时延测量：

1. 同一共享工作流收益为 4、两个独立工作流收益为 8；计算 G 不调用分账函数。
2. 同一块恢复时间 12→8，Slack 依次变为 10、13、0 时，新请求续租后的 Credit 分别为 2、0、4。
3. A/B 余额为 3/1，当前额度均为 4；只有 A 复用时变为 4/1；扣租后重放同一请求不补回余额，旧请求被拒绝。
4. 没有实际复用，即使 Agent 最新轮号从 1 变到 9，尾块检查也不续租，原余额和已处理轮号保留。
5. 内部块余额 1/2，在新请求复用后立即恢复到额度 1，后继仍在；随后尾块收租不扣内部块的余额。
6. 共享块大小为 4、A/B 信用为 3/5，在单位租金为 1 时只支付一份物理租金 4，余额变为 3/2、5/2；零信用分支不除零。
7. 准入收益 4、连续删除损失 3+2，净收益为 −1，拒绝替换；空闲容量允许零收益，有淘汰时拒绝零收益或相等收益。
8. 失败回收试算中的扣租只改变临时账本，不修改真实余额。
9. 44 个单 Agent Slack 条件下，简式与固定其他路径的 WCT 改善一致。

这些检查针对新的事件和核算语义。早期 CPU 参考文件中的“Agent 结束、延迟续租、旧准入条件”不构成本次统一流程的运行实现；本次仅复用其 WCT 计算器与示意模型，未调用旧事件策略作为正确性依据。

## 保留的边界

- 没有 Agent 结束信号，就无法确定其未来是否还会产生请求。最新已知请求信息用于恢复收益估计；历史引用不能被描述成确定仍活跃的请求。
- 固定 Agent ID 分账仍是记账约定，可能影响日后的信用分布，不宣称唯一公平。
- Credit 来源于恢复收益，按物理容量消耗；它不要求始终等于整个当前备份集合的全局价值。内部块按其前缀扩展收益续租，尾块回收前按实际当前前缀下调上限；真实净收益仍由 G−D_Y 判断。
- 逐块贪心不预付未知未来收益，也不保证发现需要多块同时加入才获益的全局最优方案。
- 图中合并展示了原子提交、分配代次与复制清理条件；真实并发协议、硬件成本校准和运行系统集成仍须另行实现验证。
