# SlackLandlord 最终流程审查：逐 Agent、逐请求、逐 KV 块

2026-09-09。审查对象是 [当前统一流程图](algorithm-2-rental-management.drawio)，不是已部署的 Mooncake/MoonKVSim 算法。

## 1. 叙述顺序与事件语义

主线明确采用：

**当前 Agent a 访问 x → 读取状态 → 等待/去重判断 → 只算 G_a,x → 只更新 c_a,x → 汇总 Credit_x → 已有副本保存，或新副本准入。**

原图把“遍历所有引用 Agent 的新副本授信”与“当前 Agent 续租”分成两条计算路径，容易让读者误以为每个请求都会重新计算其他 Agent。当前主线只有一个收益计算框、一个当前 Agent 信用更新框；无副本从空账本开始，不自动授信历史引用。

其他 Agent 没有新请求实际访问 x，就不续租；容量竞争仍按各自余额扣租。这两个动作已在图例、更新框和收租框中分别说明。

## 2. 是否覆盖一个 KV 块的完整决策

| 情况 | 流程中的处理 |
|---|---|
| 正在备份或释放 | 保存事件，操作结束后返回状态读取 |
| 重复或过期请求 | 不重算收益，不改余额，结束 |
| 当前 Agent 首次授信/新请求续租 | 只更新该 Agent，再汇总共享 Credit |
| 已有副本为内部块或读取保护块 | 可以立即续租，不受回收队列资格限制 |
| 没有副本但前缀/源不就绪 | 丢弃临时分账，先补前缀或等待源 |
| 空间足够 | 允许零信用新块，进入提交核验 |
| 空间不足且没有可释放尾块 | 拒绝候选；不突破前缀、读取或其他备份的保护 |
| 收租中候选先归零或同时归零 | 拒绝候选，丢弃整次试算 |
| 旧尾块先归零 | 试删一个，增加试算空间，检查下一轮 |
| 提交前状态/请求版本/容量失效 | 丢弃未执行试算，重新读取与计算 |
| 释放、分配或复制失败 | 清理本次未完成分配，不发布；已执行部分不伪装成回滚 |
| 当前代次操作全部成功 | 发布完整副本和租后余额，登记当前 Agent 本请求已处理 |

图中共有 27 个执行节点、30 条控制连线，所有执行节点可从入口到达，所有判断框均有两个标注出口。等待和重试明确返回状态读取；回收循环返回容量判断。

**结论：在所述事件与成本模型内，已构成一个 KV 事件的完整决策流程。** 该结论不等于并发协议、全局 WCT 最优性或实际性能已验证。

## 3. 本次审查修复的漏洞

- **历史引用自动获授信：** 新副本不再为全部历史引用初始化信用；只有实际进入流程的 Agent 获得份额。
- **请求去重隐藏在文字中：** 增加独立判断；重复、过期事件在收益计算之前退出，重试不留下未提交的“已处理”标记。
- **复制中事件覆盖余额：** 明确等待后重新读取；复制完成后其他 Agent 分别处理，不能重放旧的整块分账。
- **其他进行中备份失去前缀：** Q 排除其他备份操作保护的块，不仅排除当前候选的必要前缀。
- **只有复制失败出口：** 失败判断扩大到释放、分配和复制，避免分配失败后等待不存在的复制结果。
- **物理回滚歧义：** 未执行试算可以整体丢弃；实际已扣租、已释放的部分按物理状态处理。
- **新块支付租金后补满：** 保留既有修正，发布剩余 Credit，初次授信也登记本请求已处理。

## 4. 算术与事件检查

[audit_semantics.py](audit_semantics.py) 的 16 组检查包括：

- 2040 个单 Agent Slack 截断恒等式组合。
- 不同大小的物理块收租、共享份额比例扣租及零分母保护。
- 空闲时零信用准入、较弱/等值候选拒绝、多次试删及失败试算隔离。
- 内部/读取/其他备份操作保护块不参与回收。
- A、B 分别到达时只计算各自收益；A 新请求续租不补回 B 已花掉的信用。
- 同请求重复命中、过期请求、复制等待后重读和未提交请求标记不泄漏。

这些是有理数和局部事件账本检查。结果见 [SEMANTIC_AUDIT.json](SEMANTIC_AUDIT.json)，不作为运行实验结果。

## 5. 线条与版式

中央主线按①—⑧向下阅读；左下⑥a—⑥c组成唯一的收租循环。已有副本保存、缺失前缀等待、提交重试、执行失败的结果框均靠近对应判断。提交重试沿最右边返回②，不穿过 KV 布局或主流程框。

第一页原几何完整保留。第二页按本次要求重新组织，保留黑白样式、开头符号表和旁路 KV/Pool 布局；修订前源文件及导出已归档。

自动检查覆盖框体不重叠、判断出口、连通性、公式定界符、原生页面一致性；实际 PNG/PDF 检查公式、箭头、连线路由、文本边界与上下标。最终源哈希与查看结果在 [MANIFEST.json](MANIFEST.json)。

## 6. 必须保留的边界

Credit 表示各 Agent 独立恢复收益形成的租金优先级，不等于精确联合 workflow WCT 改善。不引入 workflow 分组、串并行判断或未来 KV 长度。

逐事件、尾块收租策略没有全局最优或竞争比证明，也不保证连续拒绝候选时旧块最终到期。没有历史引用的活跃度保证，不保存被拒绝候选的累积信用。成本校准、元数据与复制并发实现、实际吞吐/恢复时延仍需后续运行验证。
