# 本轮语义审计：独立 Agent 收益、共享 Credit

2026-09-09。当前文件是设计示意图；以下精确算术核对不代表运行部署或性能实测。

## 修正

| 原问题 | 当前处理 |
|---|---|
| 收益计算再次引入联合 workflow WCT、时间向量、固定 Agent ID 分配 | 每个 Agent 直接计算 G_a,x；只有 Credit=Σc 汇总 Agent |
| A 的 Slack 变化会连带重算 B 的授信或余额 | A 实际复用时仅更新 A；其他 Agent 完全保留余额 |
| 旧 G_x>D_Y 依赖已移除的联合收益模型 | 改为候选 x 与可释放尾块共同收租，以剩余 Credit 决定准入 |
| 仅旧块付租会使候选无需竞争即可驱逐旧块 | x 的临时信用也付租；x 先归零或同时归零均拒绝 |
| 新块复制后再次授信会退还竞争中支付的租金 | 发布竞争后的余额；初次授信登记本请求已处理 |
| 将尾块 Credit 等同于每次检查时的收益 | Credit 定义为授信减已付租金；没有实际复用不重授信或遍历重估 |
| 失败试算、物理释放、复制确认混为可回滚步骤 | 未执行试算可丢弃；已执行释放按实际状态处理，旧 ACK 不发布新副本 |
| 第一页仍含不再需要的 workflow 节点字段 | 仅调整文字为 Slack、KV 路径、请求号与版本；几何布局不变 |

新的 G_a,x 单独描述该 Agent 的 Slack 外恢复延迟减少量。以两个并行 Agent 各自从 12 降到 8 为例，各自独立收益可以都是 4，共享初始 Credit 为 8，而联合完成时间减少只有 4。该例用于说明**Credit 与精确联合 WCT 的区别**，不是算法所需的并行检测步骤。

## 精确算术与流程检查

[audit_semantics.py](audit_semantics.py) 使用有理数和局部试算账本，无旧版联合 WCT 分配器依赖，检查 12 组情况：

1. 独立 Agent 收益在 Credit 上累加，明确与联合 WCT 的差别。
2. 2040 个组合验证单 Agent 的 Slack 截断收益恒等式。
3. 新请求 Slack 更新可使本 Agent 信用上升或下降，其他 Agent 不变。
4. 同请求重复命中、旧请求、首次复制后重复命中均不重复授信。
5. 不同物理块大小、共享份额比例扣租、零余额避免除零。
6. 新块初始 5、竞争支付 2 后，发布余额为 3。
7. 较弱候选与同值候选拒绝；空闲空间允许零信用块。
8. 多次试删和零租金步长，选取确定性的物理尾块。
9. 已试删一个尾块后候选失败，实际前缀和余额完整保留。
10. 内部/读取保护块立即续租，仍不参与尾块收租。
11. 所有空间属于必要前缀或读取保护块时，Q 为空，不能准入。
12. 连续失败的试算不会消耗实际租金，不宣称无访问就必然过期。

[verify_decision_flows.py](verify_decision_flows.py) 核对 19 个执行节点可达、租后先检查候选再选择旧尾块、复制后无补满步骤、复用路径无需尾块资格、公式定界符、第一页几何、手动框位置和独立页面一致性。

实际结果见 [DESIGN_CHECKS.json](DESIGN_CHECKS.json)、[SEMANTIC_AUDIT.json](SEMANTIC_AUDIT.json)、[COMPATIBILITY.json](COMPATIBILITY.json)。原生 PNG/PDF 的排版核对及最终文件哈希见 [MANIFEST.json](MANIFEST.json)。

## 不由这些检查证明的事项
