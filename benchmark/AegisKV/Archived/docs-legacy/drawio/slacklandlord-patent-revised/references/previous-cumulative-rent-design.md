## 第三页阅读方法

左侧依次计算恢复收益、Priority 和 Credit；右侧按相同编号展示 KV 布局与数值。共享 chunk 对每个引用它的 Agent 分别计算。

贯穿示例中，Agent A 已生成 x1、x2、x3，目标 Pool 已提交 x1、x2，正在考虑备份 x3。三个块各为 2 MiB，加载每块需要 2 ms，分别重算需要 3、4、5 ms，Slack 固定为 4 ms。本例采用串行代价且同步/静默重放为 0；这些数字用于解释算法，没有声称来自实测。

1. **读取 Slack。** 取一个引用候选 chunk 的 Agent，读取其本轮 Slack。本例为 4 ms。
2. **计算现有备份的恢复时间与损失。** T₀ 表示不用该段备份时的恢复时间；Tₖ₋₁ 表示使用前 k−1 块备份的最短恢复时间。本例无备份需 12 ms，已有 x1/x2 备份需 9 ms，扣除 Slack 后分别损失 8 ms 和 5 ms。
3. **估计新方案并比较。** 假设 x3 已有效提交，加载三个块需要 2+2+2=6 ms。只有新方案更快时才采用更长前缀，否则保留旧恢复方案。
4. **扣除一次 Slack。** 恢复时间大于 Slack 时，超过的部分是损失 J；否则 J=0。时间条中，灰色表示被 Slack 吸收的部分，浅红色表示损失。本例备份 x3 后，损失由 9−4=5 ms 降为 6−4=2 ms。
5. **区分新增与累计。** 新增只比较加入 x3 前后，为 5−2=3 ms；累计比较无备份与保护到 x3，为 8−2=6 ms。右侧贡献条把累计值拆成 x1 的 1 ms、x2 的 2 ms、x3 的 3 ms。
6. **汇总共享引用。** 对每个引用 Agent 分别计算，再取累计收益最大值除以物理字节。补充例中，Agent B 具有相同恢复代价但 Slack 为 8 ms，累计收益为 4 ms；共享 x3 的排序值取 max(6,4)/2=3 ms/MiB。一份共享副本只计一次容量。
7. **计算租值和 Credit。** 新备份返回 Priority 和准入阈值，提交成功后初始化 H。旧备份逐条处理未更新的续租记录，使用对应请求到来时的 L、P 更新 H，再按当前 L 计算 Credit。回到第二页，以新增收益与淘汰损失决定是否备份。

| 允许使用的备份前沿 | 从备份加载 | 故障后重算 | 恢复时间 T | 超过 Slack 的损失 J | 相邻新增 W | 相对无备份累计 G |
|---|---|---|---|---|---|---|
| 无备份 | 无 | x1、x2、x3 | 3+4+5=12 ms | 8 ms | — | 0 ms |
| 只到 x1 | x1 | x2、x3 | 2+4+5=11 ms | 7 ms | 1 ms | 1 ms |
| 到 x2：当前状态 | x1、x2 | x3 | 2+2+5=9 ms | 5 ms | 2 ms | 3 ms |
| 到 x3：假设接纳后 | x1、x2、x3 | 无 | 2+2+2=6 ms | 2 ms | 3 ms | 6 ms |

上述 J 是专利沿用的 Slack 损失模型。共享或并行 DAG 的最终 WCT 变化仍须按整个工作流计算，不能把这里的单 Agent 示例直接推广成逐 Agent 求和。

## 1. 对象归属：Agent 保存上下文，chunk 承载物理数据

### 1.1 Agent 与 Request

管理键是 `(workflow_id, agent_instance_id, branch_id)`，不是 Agent 类型名称，也不是一次 HTTP 请求的 ID。一个 Agent 的串行多轮请求共享上下文；如果并发分叉，分配独立 branch_id，不能用后一轮 Slack 覆盖仍在执行的另一个分支。

每个上下文维护：

| 状态 | 作用 |
|---|---|
| 当前轮及固定 Slack | 新一轮请求到来时从算法 1 接收；本轮不按经过时间递减。 |
| 当前前缀根与末端 | 表示真正被本轮复用的内容；并非所有历史 KV 都仍被引用。 |
| 每层已提交前沿 | HBM 和 DRAM 分开维护，不以另一层的接纳作为前提。 |
| 续租版本与事件记录 | 记录轮次、复用范围、当时的池租金和冻结的估值输入。 |
| 生命周期及执行版本 | 区分活跃、轮间等待、关闭、故障恢复；隔离过期生产与 ACK。 |

Request 是一次生产过程：它引用 Agent 本轮快照，产生新 chunk。**Request 完成不触发 Agent 全部 KV 回收。** 在轮间等待时保留当前前缀；Agent 结束或明确放弃分支时解除相应引用。

### 1.2 共享 KV 与前缀依赖

目录按模型版本、KV 格式、布局、隔离命名空间、父前缀标识和 token 内容识别不可变 chunk。仅数据形状相同不能判定可共享。路由到不兼容目标或不同副本故障域的对象不能因为逻辑内容相同就合并物理容量。

一个逻辑 prefix trie 节点可以被多个 Agent 引用；每个目标 Pool 的物理副本只有一条记录：`chunk_id, parent_id, bytes, state, H, lease_cursor, child_count, read/copy_pins, allocation_handle, generation`。实际副本可能有多个并行分片，只有必要分片全完成才能提交。

Slack 存在 Agent 描述符中，chunk 通过引用/前缀范围查到相应快照。**不把所有 Agent 的 Slack 列表复制进每个 chunk。** 图中“Agent A / B”表示引用关系。

### 1.3 Pool 与合法尾块

每个 Pool 独立拥有累计租金 L、硬额度、可用字节、预留账本、物理目录、合法尾块最小堆 Q 和串行事件序号。主 KV 不参加备份淘汰。

Q 中的对象是**可安全删除的物理叶子**，不是每个 Agent 机械地放入一份尾块。满足以下条件才进入 Q：

- 已提交且可物理释放；没有正在读取、复制或回收的占用。
- 删除后不留下仍保留的后继块失去恢复依赖；待提交后继的依赖预留也计入。
- 不是本次候选段已有前缀的必要祖先，不是其他已锁定计划的依赖。

选择 y 后，在临时视图中删除它并更新子节点计数；父块只有失去所有受保护后继且无占用时才新暴露。共享块只进 Q 一次，也只释放一次字节。图中 A5 为 PENDING，所以 A4 暂时不能删除；P2 同时支撑 A、B 后继，也不是可直接删除的尾块。

每块只保存 H，不逐时维护一个会不断变化的 Credit 数字。Credit 在需要时由 H 与本池 L 计算。前面块虽然暂不在 Q，仍需保留其租约元数据：以后暴露时可能具有不同字节、引用及续租历史，不能只凭当前尾块的 Credit 推断它们。

## 2. 收益：累计前缀排序，联合替换判断

### 2.1 冻结可复现的评估口径

收益只来自故障恢复对工作流完成时间的改善。固定当前 Agent 轮次、Slack、可见 DAG 进度、已生成 token、代价表版本和故障场景；不能使用未来实际输出或故障结果。

恢复耗时包含本层加载、未保护后缀重算、必要的同步和静默重放。允许回退到更短的已提交前缀或全重算，因此增加可选备份不应迫使恢复变慢：

```text
T_0 = 无本段保护前缀时的预计恢复耗时
T_k = min(T_(k−1), 使用到第 k 块的加载 + 后缀重算 + 同步/静默重放)
J_(a,k) = max(T_k − s_a, 0)
W_(a,k) = max(J_(a,k−1) − J_(a,k), 0)
G_(a,k) = Σ_(j=1..k) W_(a,j) = J_(a,0) − J_(a,k)
```

这保留了专利的 J / W 公式，并将 G 改为用户要求的累计前缀收益。每块不能独立扣一次 Slack。J 是单 Agent 延迟穿过 Slack 的损失模型；对于有共享和并行分支的工作流，最终联合损失通过整个工作流的完成时间重新评估，不能直接把 Agent 的 J 相加当作精确 WCT。

部署默认的评估接口为：枚举参与保护的源故障域分别单独失效，在固定等权场景下比较工作流预计完成时间；也可以加载经校准的固定权重。候选与受害者必须使用同一场景集合/权重，每个场景中的每个工作流只计一次。J、W、G 先逐场景计算，再按固定权重汇总；不能先平均恢复时间再减 Slack。公式中的 T 省略了当前 Agent 和场景下标。这里的故障场景权重不是缓存命中概率。两个资源层分别估计其保护价值，另一层副本不替代本层判断。

代码上使用版本化代价表与残余 DAG 的增量完成时间计算，复用不受影响节点的结果；不在每次出堆时调用 LLM、运行真实故障或重放整个模拟器。预测器准确率、失效分布及控制面耗时仍是部署验证项。

### 2.2 共享对象的 Priority

共享 chunk 的排序采用明确、保守且可实现的规则：

```text
G_x = max(所有当前引用该块的 Agent 的累计前缀收益 G_(a,x))
P_x = G_x / b_x
```

最大值避免引用数膨胀和同一前缀的重复奖励。它是一项排序策略，不宣称等于共享块对所有工作流的总收益。也不直接取最小 Slack：只有各 Agent 的恢复代价曲线相同时，最小 Slack 才可能提供相应的简化关系。若多个 Agent 属于同一个工作流，其联合影响仍由最后的 WCT 比较处理。

本轮估值输入在授予租约时冻结。固定 Slack 不意味着恢复成本永远不变；当前产生的新块使用当前可见进度评估，已有租约不会因为普通生产或时间流逝被反复重写。

### 2.3 连续段 B：避免零收益前置块卡住后续恢复

候选仍由完整 chunk 构成；一次准入可以是最短连续段 B，通常只有一块。从本层已提交前沿的下一块开始，逐步补齐，找到第一个使**实际新增恢复收益为正**的完整段。只使用源侧仍可读的块，并受本池硬额度以及字节、分片数和控制面工作量上限约束。

例如前三块新增收益为 0、0、3 ms：不能永远拒绝前两块，又要求第三块必须有前缀。这里将三块作为一个有限事务统一判断。若尚未产生最后一块，或整段超过配置上限，本次返回 DEFER，等待后续状态变化；不跳过缺口，也不无限占用源主 KV。批量上限导致的机会损失是明确的工程取舍，不伪装成全局无收益结论。

```text
b(B) = 本次实际需要新分配的物理字节之和
P_B = max_a G_(a,end(B)) / b(B)
Θ = L + P_B
```

已有同池副本只增加逻辑引用，不进入新分配字节；已有 PENDING 副本加入等待者，不重复发起复制。发布时仍为每个 chunk 单独初始化 H，B 只是一项有限准入事务，不把多个块永久合并成一个对象。

### 2.4 最终收益比较

令 C 为当前本层真实保护集合，采用同一快照：

```text
ΔG_B = WCT(C) − WCT(C ∪ B)
D_Y  = WCT((C ∪ B) \ Y) − WCT(C ∪ B)
接纳条件：ΔG_B > D_Y
```

D_Y 重新计算整个淘汰集合对各个受影响工作流的影响；按物理对象、共享依赖、工作流去重。不能把逐块累计 G 或历史 Credit 相加当作 D_Y。

单块且无共享耦合时，ΔG_x 对应相邻累计前缀价值之差。前三块累计为 1、3、6 ms，第三块新增收益为 3 ms；淘汰损失为 4 ms 时应拒绝，不能使用累计 6 ms 重复支付前两块的收益。

## 3. 跨轮续租与 Lazy Refresh

新轮复用前缀时，登记事件 e：唯一事件 ID、Agent/分支、轮次、复用范围、本池当时租金 L_e，以及计算 Priority 所需的冻结快照。随后算法可以延迟兑现各块租值键：

```text
H_x ← max(H_x, max_尚未兑现事件 e (L_e + P_(e,x)))
Credit_x = b_x × max(H_x − 当前 L, 0)
```

新请求触发续租不意味着额外获得命中收益。P_(e,x) 仍只来自相应 Agent 在事件快照中的累计恢复收益；多个事件取最大截止键，不按访问次数求和。新副本首次 COMMITTED 时初始化 `H_x=L+P_x`，然后合并其间已登记的事件，不漏算也不重放同一事件。

必须使用事件时 L_e。若登记时 L=0.8、P=0.7，目标为 1.5；到刷新时 L=1.1，不能把目标改成 1.8。

### 3.1 为什么旧键可以惰性比较

续租采用 max，已有 H 不因 Slack 增大、引用退出或时间推进而追溯降低；因此已物化旧键始终不高于尚未兑现的真实租约截止键。

1. 取 Q 中最小旧键对象 y。
2. 根据其范围引用，消费截至本次规划快照的所有未处理事件。
3. 若更新后的 H_y 大于其余旧键的最小值，重新入堆并取下一个。
4. 否则 y 是当前合法候选中的最小租值键；剩余 Q 为空时比较自然成立。

无引用的对象按生命周期清理，不用“降低 H”模拟删除；被占用的对象先退出可淘汰集合，读/复制占用解除回调重新检查并补入合法叶子。新轮登记、引用变更、提交、删除和额度变化都会推进 Pool 版本，过期规划不能提交。

### 3.2 索引和复杂度

共享前缀采用不可变 trie/radix 节点加范围续租记录：登记一个已有前缀的事件不需要遍历其全部块。出堆或新暴露尾块才精算涉及该块的事件。哈希前缀查找、挂接新分支、更新引用路径和处理分片仍有实际开销，不声称所有事件 O(1)。

Q 的临时视图不能在每次准入时复制整个 Pool：本设计要求使用持久化堆根或仅覆盖本次访问节点的规划视图，删除预演只更新相应路径。已计算的续租键可按事件水位 CAS 回写缓存，不因最终 BYPASS 而必然丢掉全部刷新工作；语义事件与纯索引物化分别管理版本，不能把新水位的键混入旧快照。

实现必须限制一次决策的候选访问数、续租事件处理数和重试次数。达到上限返回 DEFER，不能把未经认证的候选当成最小项。积累的事件由后台分段压缩到块/范围的最大租值键后才能丢弃；不能仅保留“最新 Slack”而丢失历史更高的截止键。压缩与前台查询共享事件水位，保证不重复消费。

## 4. 可执行的控制流程

以下是可直接映射到控制器代码的伪代码；Pool 内元数据由单写者或短临界区串行提交，规划可在锁外使用不可变快照。等待物理释放确认和网络复制均不持有控制器锁。控制器重启后可通过事务日志恢复 RETIRING / PENDING 的清理义务，内存地址未完成隔离前不能重新交给其他事务。

```text
ON_ROUND_BEGIN(agent, request, slack, prefix):
    去重请求；创建/更新正确的 Agent 分支上下文
    固定该轮 slack，绑定兼容前缀与执行版本
    对每个 Pool 发布幂等引用/续租事件，记录该 Pool 当时 L
    对不再使用的前缀解除引用；共享副本保留其他引用
    调度待补齐前沿；正常推理继续

TRY_BACKUP(agent, pool):
    若无额度或复制许可：DEFER
    快照 ← 当前 Pool 版本、Agent 版本、故障场景与代价表版本
    B ← 从首个缺口开始的最短、完整、正收益连续段
    若当前无完整正收益 B 或达到工作预算：DEFER，等相关新事件
    若源永久不可读或 B 超出本池硬上限：本版本 BYPASS，记录原因
    Θ ← L + P_B；Y ← 空；f ← 未被其他事务预留的空闲字节
    Q ← 合法物理尾块索引的临时视图，排除 B 的祖先/占用

    当 f < b(B):
        y ← CERTIFIED_MIN(Q, 快照, 本次工作预算)
        若预算耗尽：DEFER
        若不存在 y 或 H_y ≥ Θ：BYPASS
        Y 加入 y；f 加上该物理块的实际可释放字节
        在临时视图删除 y，更新后继计数，插入新暴露的合法父块

    计算同一快照下的 ΔG_B 和联合 D_Y
    若 ΔG_B ≤ D_Y：BYPASS
    原子重验版本、合法删除顺序、源可读、额度、分片布局、占用
    若重验失败：有限次数重新规划；超限 DEFER
    短事务锁定计划与 B 的已有依赖；撤销 Y 的恢复资格并记录租金更新
    禁止新读者使用 Y；退出临界区，异步按后缀到前缀次序回收 Y
    在锁外等待 FreeACK；未确认的字节不能当作已分配地址使用
    释放回调中短事务重验事务世代、依赖及可用额度
    允许时预留 B 最终地址，建立 PENDING；否则终止本次复制计划
    若释放/预留失败：清理本事务，已淘汰 Y 不自动恢复
    将有事务 ID 的复制命令异步发给源 Worker，不持有控制器锁

CERTIFIED_MIN(Q, snapshot, budget):
    重复：
        若 Q 为空：NONE
        取最小旧键 y；丢弃失效索引条目
        若 y 当前不合法/被占用：移出当前可淘汰集合
        兑现 y 在快照水位前未处理的所有续租
        若超工作预算：DEFER
        若 Q 为空或 H_y ≤ 其余旧键最小值：返回 y
        将 y 以更新后的 H 重新入堆

ON_COPY_ACK(txn, shard):
    按 txn/分片 ID 去重；校验目标、内容/布局、执行版本与实际完成
    若任一必要分片失败或事务已取消：进入 ABORTED 清理
    若仍缺必要分片：继续等待，不发布恢复前沿
    全部分片成功时，重验前缀与故障隔离版本
    整段提交；逐块初始化 H=L+P，并合并期间登记的续租
    解除复制占用，更新 Agent 本层前沿和共享叶子堆
    唤醒因缺口或容量等待的有限待办
```

DEFER 进入有界事件队列，只在对应的完整块、额度、引用、占用或版本变化时重试，不忙轮询。源永久不可读的本版本没有恢复备份的基础，终止该版本待办，直到后续请求重新物化有效前缀。

同一段被多次提交不会重复扣容量或执行第二次续租。`CERTIFIED_MIN` 认证的是租值键最小值；最终 WCT 判断是另一项检查。算法是一种有预算的贪心租金策略，可能拒绝其他组合能满足的替换方案，不宣称全局最优或经典 Landlord 竞争比。

## 5. 异步复制、失败与生命周期

| 事件 | 必须执行的动作 |
|---|---|
| Request 正常结束 | 停止本轮生产；复制回调继续处理，保留 Agent 引用。 |
| 新轮复用 / 相同 RPC 重试 | 幂等登记事件；相同事件不重复续租。 |
| 更换前缀 / 分支取消 | 解除准确的范围引用；更新尾块合法性；其他 Agent 引用保留。 |
| Agent 最终结束 | 禁止新备份；解除引用；取消或排空属于它的待办，再回收孤立副本。 |
| 新额度低于当前用量 | 立即关停新准入、停止发出新复制批次；按安全叶子回收，必要时取消 PENDING；不要求先存在 DRAM 副本。 |
| 复制失败 / 超时 | 逻辑 ABORTED；停止新分片。正在执行的 DMA/读取必须完成或被可靠隔离后才能复用物理地址，超时本身不是 FreeACK。 |
| 某些分片成功，其余失败 | 不将整个 B 计入恢复前沿；清理其已分配数据及依赖预留。 |
| 复制期间新轮到来 | 数据身份仍有效时保留事件并在提交时合并续租；内容、路由或隔离版本失效时取消。 |
| 源失效 / 故障恢复 | 先隔离旧生产及输出；只接受可访问且版本匹配的 COMMITTED 前沿，其余重算；晚到 ACK 不得复活旧副本。 |
| 目标失效 / 重新绑定 | 失效目标的物理记录不能当作新目标的空闲副本；新 Pool/目标世代重新准入。 |
| Master 重启 | 从事务日志/Worker 目录对账；缺失完整证据的副本先隔离，不因元数据曾为 PENDING 就推断成功。 |

源 Worker 按有限读租约保护生产缓冲区。尚未发出复制时，缺少许可就等待/放弃本次备份，不无限钉住主 KV；已发出的复制须遵守真实 DMA 生命周期。前台推理优先由 Worker 的额度与传输许可实现，流程图本身不能证明低干扰效果。

HBM、DRAM 分别终结为 COMMITTED / ABORTED / BYPASS 后组合 HBM_ONLY、DRAM_ONLY、HBM_AND_DRAM、BYPASS。两层可以同时复制，不经对方中转。待一层完成不能把另一层 PENDING 标成成功。

收益门槛是指定模型下、复制成功条件下的预测替换收益；复制失败、取消、估计误差可能带来已经淘汰 Y 的损失。实现不得承诺每一次实际 WCT 都不增加，也不得用失败后的虚构回滚掩盖这个边界。

## 6. 与当前实现的具体对接

| 模块 | 当前可复用部分 | 本方案需要的调整 |
|---|---|---|
| `types.py` / `SlackSignal` | 有版本信号及分片、字节等基础类型。 | 从请求时间递减改为 Agent/分支的固定轮次快照；请求 ID 保留用于执行追踪。 |
| `slack_landlord.py` | 临时规划、Pool epoch、租金、准入/提交分离。 | `_by_request` 改为物理 prefix trie 与 Agent 范围引用；Q 按可释放叶子去重；支持有限 B。 |
| `lazy_refresh.py` | 堆顶/新暴露尾块两个刷新时机。 | 增加范围事件、水位及 max 续租；使用事件时 L，不用刷新时 L 续租。 |
| `rental_value.py` / `recovery_harm.py` | J/W、实际字节、恢复时间分解与集合损失接口。 | 去掉命中/LRU；新增累计前缀 G、共享 max 排序及工作流联合损失评估。 |
| Connector / Worker / Transfer Engine | 源侧直接复制、分片 ACK、最终内存分配。 | Agent/branch/round 与事务 ID 透传；源读租约、整段提交及取消后物理释放确认。 |
| 算法 3 | 给出 Peer HBM 额度与前台优先策略。 | 算法 2 只消费额度/许可与回收事件，不在自身重算 AIMD。 |

部署配置必须明确：最大备份段字节/分片数、每次决策访问与刷新预算、有限重试次数、源读租约与复制期限、事件压缩预算、故障场景及代价表版本。它们是资源与执行约束，不是额外的命中/LRU 收益权重。

## 7. 原文公式与本方案的关系

| 原文 / 讨论中的公式 | 本方案位置 |
|---|---|
| `J=max(T−Slack,0)`、`W=max(J_before−J_after,0)` | 第 3 页完整显示，Slack 固定到 Agent 当前轮。 |
| `G=λ_w W+λ_h U_hit+λ_l U_lru` | 按要求仅恢复，权重 1；G 改为累计前缀 W。命中/LRU 不再参与。 |
| `P=G/b`、`Θ=L+P` | 第 3 页按块与有限段分别定义；第 2 页用于接纳。 |
| `H=L+P` | 第 2 页首次提交初始化；第 3 页补充跨轮 max 续租。 |
| `Y←∅`、容量比较、`Y←Y∪{y}` | 第 2 页原生公式与判断节点。 |
| `L←max(L,max H_y)` | 第 2 页撤销/分配事务内，Y 为空不推进。 |
| `G_x>D_Y` | 因 G 已改为累计量，准入使用实际新增 ΔG_B>D_Y。 |
| Credit / 联合损失展开 | 第 3 页完整公式；属于本轮设计明确化。 |
