\begin{abstract}
Agentic applications turn one task into a dependency graph of long model and
tool calls.  A worker failure can discard substantial live key--value (KV)
state, but protecting every byte burdens healthy serving; moreover, equal-size
prefixes can have unequal workflow impact because parallel branches have
different Slack.  We present \system{}, which uses causal residual-workflow
Slack to couple normal-period protection with failure-time recovery.  At
request and tool boundaries, GBDT predicts visible remaining work and CPM
computes Slack.  \textsc{SlackLandlord} converts the resulting fail-now harm
reduction into independent DRAM and route-bound Peer-HBM admission and
eviction credits.  The source Worker owns both physical paths, and
\textsc{HBMQuotaAIMD} adjusts only the Peer-HBM envelope in response to
foreground HBM pressure.  On failure, the same Slack orders committed-prefix
loading and recomputation; complete-chunk commit, version checks, and output
fencing preserve correctness.  We re-analyze frozen SGLSim WCT artifacts from
an earlier prototype.  In a paired DP8 trial, legacy AegisKV lowers mean WCT
by 4.3\% versus no backup but is worse than host-only and peer-GPU backup; a
DP64 model projection predicts an 11.8\% reduction, and a heavy-failure
logical stress smoke reports 18.9--30.4\%.  These historical results
establish the value of avoiding KV recomputation, not the performance of the
current design: they predate its source-owned independent paths, include one
projection and small smoke tests, and execute neither physical failover nor
serving contention.  A separate 3,110-run current-design mechanism campaign
shows mean pressure rising 0.018$\rightarrow$0.590 and alpha falling
0.868$\rightarrow$0.129 as concurrency grows from 32 to 224; 92.63\% of
requests and 98.31\% of prompt tokens exhibit workflow-local prefix reuse.
These are occupancy, control, and coverage diagnostics rather than WCT or
physical-serving measurements.
\end{abstract}
