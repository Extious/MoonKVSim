## 仍影响研究论证的缺口

| 需要建立的主张 | 当前证据 | 尚缺什么 |
|---|---|---|
| AegisKV 带来可靠的完整 workflow 收益 | Full−DRAM 平均故障罚时 `+0.031571 s`，95% CI `[-0.159076,+0.222218] s`；健康流量约增加 91.8% | 用预先确定的实际目标场景证明效果；若仍无收益，应保留负结果并重新评估贡献，不能挑种子 |
| 各算法对效果不可替代 | 三组消融和七设置敏感性的整体/重点 workflow 区间均跨零 | 足够重复且机制可辨别的场景、代价/收益分解；流量改善不能替代 WCT 改善 |
| 真实系统可获得模拟中的效果 | DP2 RTX4090 pilot 只验证功能；每臂一次故障，full batch 约慢 0.46%；DRAM 无自然准入 | 真实请求、自然双层准入、配对重复、故障/恢复/清理全链证据及实机对照；不能把定向机制测试计作自然收益 |
| 模拟时序可信 | 170 次完整 CPU 模拟和事件审计；理想时长 CPM、A100 服务参数未校准 | 目标平台 prefill/decode、混合 batch、copy contention、controller 开销校准及误差分布 |
| 面向长上下文 agent 的 Slack 可用 | 实机预测器训练/校准/测试为 40/20/20 个短合成 workflow；模拟使用理想时长 | workflow-disjoint 的真实长上下文预测验证、因果特征和缺失结构处理；不能用 ideal Slack 当预测器结果 |
| 覆盖 128K | 最大 context 86,214 tokens，128K bucket 为零 | 如果论文要主张该范围，需要观测到的真实输入与实际执行；不通过填充或截断制造覆盖 |
| 并发恢复语义与实机一致 | 元数据差分和 finalizer 序列通过；模拟 pin 强于原生 lease | activation→load 与压力淘汰竞争的物理测试、fallback/资源守恒验证；当前不应称全数据面等价 |
| 相对既有系统有清楚优势 | 已文献定位，但 DRAM-only 是 AegisKV 自身控制 | 合适且公平的外部 baseline、匹配资源/故障/工作负载与各系统功能边界；没有测量不能画对比胜率 |

## 后续实验应如何保持可信

先固定实现语义，尤其是恢复保留与淘汰竞争；再冻结源码、工作负载和故障计划。
在此基础上分别做目标硬件时序校准、真实 predictor 验证和自然双层保护实验。
预先确定比较指标、重复单位及故障选择规则，报告所有配对观测、完整工作负载 WCT、
队列/恢复局部指标和保护代价。新增数据有可能继续显示无收益，应原样保留。
