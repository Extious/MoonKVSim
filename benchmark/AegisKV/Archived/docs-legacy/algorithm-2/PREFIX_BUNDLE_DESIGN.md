# SlackLandlord：最小可执行决策

2026-09-08 简化版。[两页 Draw.io](../drawio/slacklandlord-patent-revised/algorithm-2-patent-revised.drawio) 的第 1 页介绍 Agent 与共享 KV，第 2 页完整展示下面的流程。

**一个候选是某个 Agent 的连续备份前缀；只有它带来的 WCT 收益大于腾出空间的 WCT 损失，才执行替换。** 实际分配、复制和回收仍以物理 chunk 为单位。

删去上一版在线流程中的动态规划、分支搜索、分数松弛、最优性 gap 和跨轮区间证明。保留真实恢复收益、合法前缀、容量租金和按需刷新。[simple_slacklandlord.py](simple_slacklandlord.py) 是对应的 CPU 决策参考，未接入 Mooncake 或 MoonKVSim 的运行路径。

## 1. 收益：沿用专利的 G、W、J

图中符号说明位于流程开头，完整对应表见[图件说明](../drawio/slacklandlord-patent-revised/README.md)。本页省略资源层下标 r；a 表示 Agent。候选 X 是从单块 x 扩展出的新增连续块集合，单块时 X={x}。

沿用专利的恢复损失与恢复收益定义：

\[
J_a=\max(T_a-s_a,0),\qquad
G_X=W_X=J_{\text{加入前}}-J_{\text{加入后}}.
\]

T_a 是加载可用前缀、重算剩余 KV 的最短恢复时间；s_a 是该 Agent 的本轮 Slack。恢复器可选择更短的可用前缀，因此备份增加不会使最短恢复时间变大。重算、读取时间来自恢复代价模型。本轮 Slack 固定；新请求才替换对应 Agent 的本轮输入。

只有一个受影响 Agent 时，J 就是上述 J_a。多个 Agent 受影响时，将恢复延迟加到当前工作流 DAG 的对应节点，按依赖计算完成时间；**J 表示相关工作流相比正常执行多出的总 WCT**。同一工作流联合计算，不能直接相加各 Agent 的 J_a；不同工作流的 WCT 损失可以相加。多个故障场景沿用明确给定的场景权重，所有数值仍是该模型内的条件收益。

新请求只替换对应 Agent 的输入，但可能改变同一工作流的关键路径。共享块对所有相关工作流的影响都进入 J，物理空间只计一次。按此前确定的范围，仅保留恢复收益，故 G_X=W_X；相当于原专利的恢复权重取 1，命中和 LRU 权重取 0。

## 2. 一次容量决策

对每个 Agent，从首个未备份的完整块开始，依次尝试所有可读、完整的连续前缀终点。每个候选都独立从 Pool 当前状态开始：

1. 先假设备份候选缺少的连续块 X，计算 G_X。初始化拟淘汰集合 Y 为空、联合损失 D_Y=0、可用字节 f 为当前空闲字节。这是元数据试算，尚未分配显存。
2. 若 f<b_X，在可释放的物理尾块中选择当前单位字节优先级最小者：

   \[
   G_y=J_{\text{删后}}-J_{\text{删前}},\qquad P_y=G_y/b_y.
   \]

   **这里的“删前/删后”都在已经假设备份 X 的状态下计算。** 尾块必须没有仍保留的物理后继；候选完整前缀及其祖先、正在被读取固定的前缀均不能选。相同 P_y 按稳定 chunk ID 决定。

   每试删一块就更新：

   \[
   Y\leftarrow Y\cup\{y\},\quad D_Y\leftarrow D_Y+G_y,\quad f\leftarrow f+b_y.
   \]

   随后比较新暴露的物理尾块；f≥b_X 时立即停止。找不到可释放尾块则跳过本候选。X 只包含尚未备份的物理块，所以共享对象不重复占用 b_X；Y 中的物理块也只释放一次。
3. D_Y 是这次试删造成的联合恢复损失，用它结算容量租金：

   \[
   \mathrm{Credit}_X=G_X-D_Y.
   \]

   D_Y 必须累计**各次试删当时**的 G_y，顺次做差等于从“加入 X 后”到“试删 Y 后”的总损失，不能相加旧缓存中的固定收益。P_y 的单位是 ms/byte，G_X、D_Y、Credit_X 的单位是 ms；空间充足时 D_Y=0。
4. 所有候选比较后，执行正 Credit_X 最大者；并列时优先选择变动字节少者，再按稳定 ID 决定。没有正 Credit_X 则保持现状。下一次新请求、新完整块或容量变化会再次触发决策。

Priority 继续使用 P，联合淘汰损失继续使用 D_Y。Credit_X 对应整个合法替换的净收益。**不保存固定的每块历史 Credit，不按一个全局过期阈值连带淘汰前缀。** 当只缺一块空间时，只回收一块。

租金仍采用上一版的**容量竞争**含义；本次用实际回收损失直接结算，去掉求解容量价格 λ 的松弛问题。它不是旧版累计 L 扣减余额的 Landlord，不能称为已经实现“Agent 分账续租”。新轮只更新该 Agent 的模型输入，不存在给其他 Agent 补回已消耗余额的操作。若必须恢复历史分账扣租，需要另一个明确的账本目标；本版没有把两种语义混用。

## 3. Lazy Refresh 保留什么

新请求到来时只标记相关工作流的收益缓存需要更新；连续多个更新可以合并。真正计算 G_X 或 P_y 时，才重算**本轮输入或备份前缀已改变**的工作流；其他工作流的缓存直接复用。

缓存有效条件同时包括工作流输入版本和各 Agent 的备份前缀。删尾后新暴露的尾块必须用当前试算状态计算损失，不拿旧优先级继续排序。没有维护区间、上下界或“旧键一定只升不降”的假设。

调用方跨事件保留一个 `LazyValue` 实例，并将它传给 `decide(..., values=...)`；输入改变时调用 `update`，该调用本身不计算工作流收益。若每次重新创建缓存，就没有跨事件的复用收益。

这是延迟计算、避免重复计算的收益；不保证每次决策只需重算一个尾块。若所有相关工作流都改变，或者首次访问大量前缀，仍需重新评估。CPU 参考计数只衡量收益缓存的实际计算，不能当作部署时延测量。

## 4. 前面问题如何处理

| 问题 | 最小规则 |
|---|---|
| 尾块价值高，是否导致整个前缀一起淘汰 | 比较当前截短损失，空间足够立即停止；无统一过期判定 |
| 请求尚未结束，新块就没有竞争力 | 本次不备份；保留已有前缀，下一个完整块到来后重新评估 |
| 第一块收益为零，后面合起来有收益 | 尝试所有已生成的连续终点，不在第一个零收益块处停止 |
| 新轮复用已有 KV | 更新该 Agent 的输入，保留共享对象；需要收益时再刷新 |
| 不同 Agent 复用同一块 | 物理去重，联合计算相关工作流的 WCT 变化 |
| 同一工作流的并行 Agent | 用 DAG 的完成时间计价，避免重复计算共享关键路径收益 |
| 容量缩小 | 暂停准入，直接按当前损失密度逐块回收至 C；固定读取阻碍时等待 |
| 复制尚未完成或回收正在进行 | 完成上一轮操作后再做下一轮分配；COPYING/RETIRING 仍占容量 |

执行顺序是：重新检查版本、容量与固定引用，撤销被淘汰后缀的恢复可见性，等待实际释放，再分配并复制。所有分片确认成功后才发布连续前缀；失败时不发布新备份，并回收失败分配。元数据草案的净收益不保证复制失败后的实际收益；已释放副本不能自动恢复。这些是执行层应提供的接口约束，不需要在算法图中展开成另一套协议。

## 5. 这版保证什么，放弃什么

在输入模型固定且方案成功执行的条件下，普通准入严格降低模型中的总 WCT 损失 J，保证前缀合法、共享容量只计一次、固定引用不被回收。强制缩额可能降低收益，但不会将负收益回收伪装成有益准入。

**选择过程是贪心局部替换，Credit 的计算不是启发式评分。** 不承诺全局最优或竞争比。一个候选只扩展一个 Agent 的路径；多个互不共享的 Agent 需要同时备份才有收益时，可能漏掉该联合方案。即使每个候选的价值算得准确，按损失密度逐块回收也可能错过更好的组合。这是本次删除全局组合求解的明确取舍，不能宣称已解决任意共享 DAG 的最优分配。

参考代码每轮尝试 M 个连续终点，每个候选最多回收 N 块、每次最多比较 N 个尾块，因此至多 O(M·N²) 次缓存查询；缓存失效时还需执行相关 DAG 计算。它没有指数级组合搜索，但生产部署仍需对实际前缀数、决策频率和延迟进行测量。
