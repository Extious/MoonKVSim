# SlackLandlord：Agent 子租约与尾块收租

2026-09-08。本版恢复授信、续租、扣租与租值键，保留 Agent 生命周期管理 KV、单物理 chunk 决策和连续前缀恢复。它是**设计与 CPU 可执行参考**，尚未接入 Mooncake / MoonKVSim 复制路径。

## 1. 三个冲突分别怎么改

| 冲突 | 本版规则 | 代价或边界 |
|---|---|---|
| H=L+最新 P 会补回已经消耗的信用；新请求逐块重算又失去 Lazy Refresh | 新请求只更新 Agent 轮号与输入，登记一次续租资格。块下次参加收租时兑现；普通刷新只允许减额 | 这是延迟兑现的协议，不声称等价于“请求时已按当时收益逐块授信”的另一个算法 |
| A 续租却同时补回 B、C 的余额；同一工作流收益不可随意相加 | 每块按 Agent 分账，只允许 A 补充信用；其他 Agent 保留已扣租余额，必要时下调。物理块只收一份租金，同一工作流先联合计算再分账 | 联合收益的归属不唯一，本版明确使用固定 Agent 顺序的精确边际贡献 |
| 内部块不能独立回收，全池持续扣租却使它先于高价值尾块耗尽；陈旧 H 也未必是下界 | 只对可独立释放的尾块收租；内部块和固定读取块保存剩余信用。推进 L 前检查全部可释放尾块 | 不继承经典全池 Landlord 的竞争比；第一次回收可能扫描全部尾块 |

**Agent 决定何时有续租资格，物理 chunk 决定收多少容量租金，连续前缀决定何时参加回收竞争。** 内部块仍计入容量，但不作为独立可回收资源扣租；这不是对全部驻留字节按时间收费的账单。

## 2. 生命周期与最少状态

| 对象/事件 | 状态与动作 |
|---|---|
| Agent / 执行分支 | 生命周期 ID、当前 Request 轮号、本轮 Slack、KV 路径、工作流节点与代价版本；请求内 Slack 不变 |
| 新请求 | 只改对应 Agent 表；已备份块保留旧缓存与余额。重复投递同一轮号不重复续租 |
| 请求结束 | 保留 Agent 的 KV 引用和子租约，支持下一轮使用 |
| Agent 结束 / 引用解除 | 撤销自己的子租约，不把余额转给其他 Agent。在块下次参与收租前清理；一个 Agent 结束不直接删除共享物理块 |
| chunk | 物理 ID、父子关系、实际字节、分配代次、提交与固定读取状态；Agent ID → 剩余信用、已兑现轮号 |
| Pool | 算法 3 给出的备份可用容量、实际分配、累计租金 L、当前可释放尾块 |

并行执行分支需要独立的当前输入记录，不能用后到请求覆盖仍在执行分支的 Slack。Agent 结束后再次使用同名对象时更换生命周期代次，避免兑现旧事件。Slack 通过 Agent 表间接读取，不能复制到每块后逐项修改。

## 3. 信用来自什么收益

时间量以 ms 计，b_x 是物理 bytes，tokens 仅说明内容大小。下面针对给定故障条件计算恢复收益，不加入命中、LRU 或带宽奖励。多个故障条件可以按预先固定、总和为 1 的权重求期望。

G、c、Credit、D 的单位为 ms；P、H、L、δ 的单位为 ms/byte。租金是用于容量竞争的信用消耗量，不是墙上时间，也不另行估算算法 3 已约束的前台推理影响。

n_a 是 Agent 当前已生成的块数，k 是连续备份长度：

\[
T_a(k)=\min_{0\le j\le k}
\{t_a^{\mathrm{reuse}}(j)+t_a^{\mathrm{recompute}}(j,n_a)\}.
\]

reuse 是加载并使用整个前 j 块备份的耗时，recompute 是在此前缀可用时重算 j+1 至 n_a 的耗时，已计入前面 KV 对后续重算的作用。沿用用户在图中修改的 reuse / recompute 名称，对应早期文档的 load / rec，未添加正常请求的命中复用收益。采用先加载再重算的代价模型；min 允许退回较短前缀或完全重算，不支持断裂备份后缀。T_a(k) 计算恢复全部 n_a 块已生成 KV 的耗时。

一个工作流只有该 Agent 的恢复耗时改变时，s_a 是在其余恢复耗时固定条件下由工作流路径计算的有效 Slack：

\[
\Delta T_{a,x}=T_a(k)-T_a(k+1),\qquad
W_{a,x}=\min\{\Delta T_{a,x},\max(T_a(k)-s_a,0)\}.
\]

固定 Slack 仍会限制收益。若其他并行恢复也发生变化，不能机械套用原始单 Agent Slack，统一采用 DAG：

\[
t_v=d_v+T_v+\max_{u\to v}t_u,\qquad
\mathrm{WCT}_w(\mathbf T)=\max_{v\in w}t_v,\qquad\max\varnothing=0.
\]

受影响 Agent 节点取 T_v=T_a(k_a)，其余节点恢复耗时为零；d_v 是正常执行耗时。W_{a,x} 统一表示归属于 Agent a、不重复计价的 WCT 收益份额。工作流只有一个引用 Agent 时可用上面的 Slack 简式；同一工作流内多个 Agent 引用 x 时，改用下面的共享分账式，不把两种算法相加。

已有尾块的收益以少该尾块的前缀与保留该尾块的前缀计算。试删其他块后重算条件收益，不能把各块信用之和当作整个工作流收益。

### 共享块如何分账

固定按稳定 Agent ID 顺序 a_1,…,a_m 计账。T^(i) 让前 i 个引用 Agent 使用 x，其余引用 Agent 使用少一块的前缀：

\[
W_{a_i,x}=\sum_{w\gets x}
[\mathrm{WCT}_w(\mathbf T^{(i-1)})-\mathrm{WCT}_w(\mathbf T^{(i)})],
\qquad\sum_iW_{a_i,x}=G_x.
\]

这些中间恢复向量只用于分账，物理块仍复制一次。每份信用是非负的模型差值，总额精确等于该块联合收益；没有人为奖金或平均分配系数。

**顺序是协议约定，不是 WCT 唯一决定的公平分配。** 并行互补的恢复可能让前一个 Agent 分得零、后一个分得联合收益。顺序固定，不因 Slack 或请求先后重排。需要对称公平时必须另行研究，不能声称本版已经解决。

### 直接计算 Agent 的收益密度

\[
P_{a,x}=W_{a,x}/b_x,\qquad
G_x=\sum_a W_{a,x}=b_x\sum_aP_{a,x}.
\]

P_{a,x} 保留 Agent 下标，用于该 Agent 的子租约；G_x 只汇总一次，供准入与回收损失比较。删除主流程中独立的③c以及 G_x=W_x 的重复转写，不再维护单独 W_x 或 G_{a,x} 记号。CPU 参考的 CostOracle.shares 返回值对应这里的 W_{a,x}；本次只调整表达与符号，账本决策未改变。

## 4. 续租、限额与租值键

c_{a,x} 是 Agent a 的剩余信用，Credit_x 是该物理块的总余额：

\[
\mathrm{Credit}_x=\sum_a c_{a,x}.
\]

首次复制成功提交时初始化 c_{a,x}=b_xP_{a,x}=W_{a,x} 并记录轮号。已有块进入收租检查时，按当前恢复状态更新各 Agent 的 W_{a,x} 与 P_{a,x}，逐 Agent 执行：

\[
c_{a,x}\leftarrow\begin{cases}
0,&\text{生命周期结束或引用解除};\\
b_xP_{a,x},&\text{有未兑现的新请求轮号};\\
\min(c_{a,x},b_xP_{a,x}),&\text{该轮已兑现}.
\end{cases}
\]

然后记录已兑现轮号。首次加入该块的 Agent 子租约按当前轮号登记；已经兑现的记录不能因引用解除而抹掉，否则同一轮解除后再引用会重复授信。生命周期代次确保结束后不会重新使用旧身份。

A 新请求只允许 A 补充信用；其他 Agent 可因真实价值下降减额，却不能增加余额。检查后总剩余信用不超过该块当前条件恢复收益。代价变化、缓存失效、成为堆顶或新尾块均不单独授予续租资格。

对当前参加收租的尾块：

\[
H_x=L+\mathrm{Credit}_x/b_x.
\]

只有首次完整授信且没有消耗时才有 H_x=L+Σ_a P_{a,x}。普通刷新不能用最新收益的总额覆盖已扣租余额。**Credit 是剩余租金信用，与 G_x-D_Y 的净收益检查分别维护。**

## 5. 收租与前缀暂停

E 是试算状态中所有可独立释放的物理尾块：没有已提交后继、未被固定读取、不属于候选 x 的必要前缀。全部实际分配仍计入容量。

推进租金前检查 E 中每个块的输入与轮号，兑现续租、限额并更新 H。不能只检查旧堆顶，因为另一块的键可能已经下降。

\[
\delta=\min_{y\in E}\frac{\mathrm{Credit}_y}{b_y},\qquad L\leftarrow L+\delta.
\]

每个 y∈E 按收租前总余额的比例分摊一份物理租金：

\[
c_{a,y}\leftarrow c_{a,y}\left(1-\frac{b_y\delta}{\mathrm{Credit}_y}\right),
\qquad\mathrm{Credit}_y\leftarrow\mathrm{Credit}_y-b_y\delta.
\]

Credit_y=0 时不做除法，直接可淘汰，此时 δ=0。最小值规则确保非负；每块各 Agent 共支付 b_yδ，多引用不使物理租金翻倍。选一个归零尾块，按物理 ID 解决同值选择；删后重新检查新暴露的尾块。

内部块与固定读取块保存原剩余 c，不随 L 扣租，也没有有效的回收 H。重新暴露后先执行第 4 节规则，再用当前 L 和**保存的剩余信用**构造 H。没有新请求就不补回完整 G。

所以较新、高价值的尾块仍可能有较高初始信用，但收租时内部前缀不会暗中耗尽。尾块删除后，前缀独立参加下一次竞争。若前缀真实收益为零，仍可能继续淘汰；避免的是错误的必然连锁结论，并非保证总能保留前缀。

## 6. Lazy Refresh 的准确含义

1. 新请求只更新 Agent 轮号、Slack 与代价引用，不遍历其所有 KV。
2. 内部块保存余额与已兑现轮号，期间不欠独立尾块租金。
3. 下次参与收租时检查引用版本，有新轮号才兑现一次续租，其余份额只保留或下调；收益按**兑现时**的恢复状态计算。
4. 推进 L 前必须完成所有参与块的检查，不允许先跳过它收租、后来再补完整信用。
5. 两次参加收租之间同一 Agent 的多个新请求可合并为最新轮号，因为是替换型续租、不累加。如果中间发生该块应支付的租金，则必定已经兑现当时轮号。

因此无需保存无限历史事件或每轮完整快照，但要接受延迟兑现的定价时点。这不是把请求时已经确定的授信偷偷挪到将来的 L。

保留两项优化：延迟收益计算与续租兑现，以及部署时用 H/L 表示延迟扣租。CPU 参考为便于审计而显式扣每个参与尾块的信用，没有声称实现生产堆优化。重复刷新同版本复用 DAG 缓存，也不授信。

## 7. 单个完整 chunk x 的准入

1. 已备份则更新逻辑引用并 REUSE。源不完整/不可读、必要前缀未提交时等待或跳过本轮后续备份。
2. 固定 x 的必要前缀，计算 G_x；G_x≤0 则 BYPASS。若已超过算法 3 的新容量，先强制回收。
3. 在临时计划中加入 x，初始化 Y=∅、D_Y=0。x 尚无物理租约，不收租。
4. 空间不足时，对合法尾块刷新、续租限额、收租、试删归零尾块。逐次累计**当前条件 WCT 损失**到 D_Y；后续收益使用前次试删后的状态。
5. 容量足够且 G_x>D_Y 才接纳，否则丢弃计划。失败试算不扣真实租金、不删除备份、不消耗真实账本中的待续租轮号。
6. 重验版本、固定读取与分配代次。物理释放 ACK 后才可给 x 分配空间；所有分片成功才发布 COMMITTED 与新块信用。

逐次损失望远镜相消，所以模型内 G_x-D_Y 精确等于整个成功替换的 WCT 改善。D_Y 是回收损失，不能再称为累计租金。租金决定历史余额与回收顺序；净收益检查防止一次成功准入牺牲更大的恢复收益。

容量缩小时没有正净收益要求，沿同一尾块收租规则回收。固定读取阻碍目标时等待解除，不能假称已释放容量。COPYING / RETIRING 分配在释放 ACK 前仍占用空间。

参考把接纳视为原子元数据提交。真实复制失败时，已经释放的旧备份通常不能回滚：清理 x 的未提交分配，保留有效前缀，重新规划；此时不适用“成功替换净收益为正”的结论。部署仍需复制协议与故障注入验证。

## 8. 验证与边界

[AGENT_LEASE_VALIDATION.json](AGENT_LEASE_VALIDATION.json)覆盖单 Agent 续租、重复事件、物理租金分摊、共享工作流总额、刷新不补信用、前缀暂停、带已消耗余额的重新暴露、非旧堆顶键下降、生命周期结束、试算回滚、容量/固定读取和随机小森林的独立 DAG 核算。

本 CPU 模型内可检查或直接推导：

- 信用非负；已有子租约没有新请求时，刷新不增加余额。首次物理复制或首次加入的新 Agent 子租约可以初始化授信。
- 一份物理租金按子租约分摊；单块共享分账之和等于联合收益。
- 只删合法尾块，成功方案不超容量且仅加入一个新物理块。
- 每次收租至少产生一个零信用尾块，每次试删少一块，有限块数下循环终止。
- 固定输入下普通成功准入严格降低模型 WCT，但不保证找到全部有利替换。

**保留限制：** 严格单块正收益门槛可能拒绝零收益前置块，错过多块组合；历史信用的回收顺序可能错过另一个更好交换；暂停内部块租金不是最优容量定价；固定顺序分账不对称。未证明经典竞争比、全局最优、唯一公平性、实现开销上界或实测 WCT 提升。

Young 的 [On-Line File Caching](https://www.cs.ucr.edu/~neal/publication/Young02Online.pdf) 图 1 对所有缓存文件按大小收租，脚注 3 将动态读取成本排除在分析之外。本版改变了这些条件，需要独立评价，不能直接继承该文保证。

后续比较本版、仅按当前收益的版本、旧 H/L 策略时，应记录 WCT、前缀长度、写入/回收次数、每事件检查尾块数和实际 DAG 计算次数。当前 CPU 核算不替代这些实验。
