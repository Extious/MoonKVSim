\begin{abstract}
An agent workflow completes when its dependencies complete, so reducing one
request's recovery time need not reduce task latency. AegisKV uses residual
workflow Slack to value independent source-owned protection in Peer-HBM and
Mooncake Store DRAM. We revise admission to value shared-prefix deletion
closures, group already-sealed chunks, and retain old protection until an
asynchronous replacement commits. A foreground-constrained controller
replaces windowed AIMD with allocator reservations, acknowledged reclamation
and calibrated copy allowances. An executable event reference checks the
revised contracts; device integration and interference calibration remain
unvalidated. The earlier Mooncake prototype and aligned simulation provide
separate evidence: 260 native policy cases, a small two-RTX4090 functional
recovery pilot, and \MeasuredRuns{} executions of 160 complete FanOutQA-derived
tasks across five paired admission orders. \AbstractResults{}
These earlier results do not evaluate the revised algorithms. All modeled
latency remains conditional on prescribed service and uncalibrated hardware.
\end{abstract}
