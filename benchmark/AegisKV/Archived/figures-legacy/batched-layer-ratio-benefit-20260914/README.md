## 读图

- **下横轴：**初始在 Peer HBM 备份前多少层，同时也是流水线每批的层数，完整扫描 1–36 层。
- **上横轴：**初始 Peer HBM 历史 KV 占用。沿用 Qwen3-8B、TP=1、历史 32K 时每层 128 MiB 的容量口径；只用于将层数转换为初始备份容量。
- **纵轴：**相对完全没有 Peer HBM 备份的总延迟降低百分比，越往上越好。总延迟包含全部重放计算与暴露出来的 KV 加载等待。
- **五条曲线：**单层历史 KV 传输耗时分别为单层重放计算耗时的 0.5、1、1.25、2、4 倍。这五个倍数是解析参数，未伪装成特定带宽或 N 的实测值。
- **点的形状：**实心圆是固定倍数内的帕累托点，叉号是被支配点；目标为初始容量更少、相对收益更大。各条曲线分别判定，不跨倍数排名。

| 单层传输耗时为计算的 | 首次达到收益平台的前层数 | 初始容量 | 最大相对收益 |
|---:|---:|---:|---:|
| 0.5 倍 | 1 | 128 MiB | 1.37% |
| 1 倍 | 1 | 128 MiB | 2.70% |
| 1.25 倍 | 20 | 2560 MiB | 21.74% |
| 2 倍 | 24 | 3072 MiB | 50.68% |
| 4 倍 | 29 | 3712 MiB | 75.17% |

传输不慢于计算时，备份第一层后，后续加载已能被计算覆盖；因此增加备份层数不再提高收益。相对无备份仍然节省了第一层的启动加载时间，故 0.5 倍和 1 倍曲线分别为 1.37%、2.70%，均不是零。

传输相对计算更慢时，更多加载暴露在关键路径上，扩大前层备份可以获得更大收益。由于初始备份容量与每批层数一起变化，且最后一批采用实际剩余层数，曲线存在真实的局部下降；没有平滑、填充尾批或只保留能整除 36 的批大小。平台起点是达到最大收益的最低容量，不是无条件的唯一最佳策略；平台之前还有多个容量和收益之间的帕累托取舍。

## 基线和时间归一化

沿用此前相对收益主图的固定分母口径：每个倍数下，在每批 1–36 层的无备份方案中选最低总延迟，并让该倍数整条曲线共用它。本组最优无备份批大小均为 1 层。无备份时所有历史 KV 初始在 Host DRAM，也采用流水加载；第一批必须先加载，启动等待计入基线。

有备份方案的前一批 KV 在执行起点已经就绪。计算当前批时只加载下一批，下一批全部 KV 到齐后才能切换；已加载 KV 保留。初始备份容量不是整个恢复过程的峰值 HBM 上限。

为了只研究相对收益，脚本将单层计算时间设为一个时间单位，传输时间按给定倍数设置。它们不是 GPU 实测毫秒数。将全部计算和传输时间按相同倍数缩放后，延迟也同比缩放，而相对收益和帕累托分类不变。因而在当前均匀层耗时、固定层数与流水规则下，时间比值和备份层数足以描述相对收益。

这不代表绝对时间差可以单独确定相对收益，也不代表真实系统的全部影响都被两个变量覆盖。若加入逐层异质性、复制启动开销、计算与复制争用、额外固定延迟，或改变流水规则，就需要重新检查能否合并。图中不计故障检测、接管排队、权重加载、备份维护和前台竞争。


主图包含 5 个倍数、180 个有备份解析配置，另计算相同批大小的 180 个无备份配置用于选择基线。没有 GPU 实验或统计重复，不绘制置信区间。
