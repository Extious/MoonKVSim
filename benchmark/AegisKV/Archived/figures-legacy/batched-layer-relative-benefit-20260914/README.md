## 主图的比较口径

每条曲线固定带宽、历史长度与重放工作量；备份方案同时变化每批层数和初始驻留前层数。无备份方案的全部历史 KV 仍保存在 Host DRAM，恢复时也进行分批流水加载，第一批必须先从 Host DRAM 加载后才能开始重放。

为使一条曲线中的百分比可直接比较，**同一条曲线共用一个无备份延迟基线**：在每批 1–36 层的无备份方案中取最低延迟。本组七种条件中，最低延迟均由每批 1 层取得。这是当前模型的扫描结果，不是对硬件最优批大小的断言。模型忽略复制启动开销；加入真实启动成本、争用与测量结果后，最优无备份批大小可能改变。

百分比表示相对该基线节省的时间，占该基线延迟的比例。0% 表示没有改善，正值表示延迟更短；计算时间仍然存在，因此零加载等待不等于 100% 收益。按用户对相对收益图的最新确认，主图与同批配对版的纵轴均采用**低值在下、高值在上**：越靠上表示收益越大。图例和标注随坐标方向调整，数据、基线与帕累托判定不变。

主图实心圆是在固定条件内，以初始 Peer HBM 容量更少、相对收益更大为目标的帕累托点；叉号是被支配点。由于分母固定，这与容量和实际延迟的帕累托集合完全一致。不同带宽、不同重放长度分别归一化、分别判定帕累托；不能把不同工作量的百分比当成相同绝对时间，也没有计入带宽获取成本。

## 三个面板

- **a：基准。** 固定 H2D 25 GB/s，重放 512 token。统一无备份基线为 198.02 ms。前 20 层备份达到本条件最大收益 13.72%；继续增加初始容量，延迟与收益都不再改善。所有 1–36 层数据均保留，包括尾批造成的非单调变化。
- **b：带宽。** 重放固定为 512 token，对比 12.5、25、50 GB/s，每种带宽使用自身的无备份基线。较高带宽下，无备份流水已经能隐藏更多传输，因此备份带来的额外相对收益较小。三种带宽的最大收益分别为 56.34%、13.72%、1.55%。
- **c：重放长度。** H2D 固定为 25 GB/s，对比 128、256、512、1024、2048 token，每种重放长度使用自身的无备份基线。重放计算增加既提供更多覆盖传输的时间，也增加总延迟的计算部分。在本组条件下，较长重放使备份的相对收益变小。1024 与 2048 token 的收益分别恒为 1.54% 和 0.77%；两条曲线分别绘制并直接标出数值。此前等待曲线完全重合，不能在新指标下继续合并。

## 配套：同批大小配对版

[同批配对 PDF](/home/comp/zhanzhao/MoonKVSim/output/pdf/batched-layer-relative-benefit-20260914/relative-benefit-matched-batch.pdf) · [PNG](/home/comp/zhanzhao/MoonKVSim/output/pdf/batched-layer-relative-benefit-20260914/relative-benefit-matched-batch.png)

此版回答“保持流水批大小不变时，备份第一批本身节省多少延迟”。每个点的无备份方案使用与备份方案相同的每批层数，因此它的分母沿横轴变化。两边都采用只预取下一批、整批就绪后切换的调度。无备份需要先加载第一批，此后整个时间线相对有备份版本向后移动第一批的加载时间。

同批对比能隔离第一批备份的影响，但不能将不同批大小的收益百分比上升直接解读为实际延迟下降。示例为 25 GB/s、重放 512 token：

| 初始前层数 / 每批层数 | 有备份延迟（ms） | 统一基线收益 | 同批无备份延迟（ms） | 同批配对收益 |
|---:|---:|---:|---:|---:|
| 1 | 192.65 | 2.71% | 198.02 | 2.71% |
| 6 | 189.54 | 4.28% | 221.75 | 14.53% |
| 20 | 170.86 | 13.72% | 278.23 | 38.59% |
| 36 | 170.86 | 13.72% | 364.13 | 53.08% |

前 20 层与前 36 层的有备份延迟相同，但同批配对百分比从 38.59% 增加至 53.08%，原因是对应的无备份基线变慢了。故将统一基线版用作容量与延迟取舍的主图；同批版所有圆点仅表示候选配置，不复用旧图的帕累托标记。

## 模型与证据边界

沿用原有 Qwen3-8B 结构解析成本：36 层、TP=1、历史 32768 token、每层历史主 KV 128 MiB、假设有效算力 100 TFLOP/s。H2D 有效带宽假设为 12.5、25、50 GB/s；整层计算包含实际仍需执行的重放计算及其历史注意力成本。Peer 是预先指定的接管 DP，前层 KV 在恢复起点已经就绪。

初始备份层数与每批层数同时变化，这是容量和分批方式的联合比较；所有尾批使用实际剩余层数。只预取下一批，整批 KV 到齐后才切换，已加载历史 KV 保留。初始 Peer HBM 占用不是恢复期间的峰值容量上限。

时间从接管执行端可以开始加载和重放时计起，到最后一层重放完成为止；不含故障检测、接管排队、权重加载、备份维护、前台竞争或复制启动开销。假设一个计算流与一个 H2D 流可重叠且不互相降速。这些结果为**未校准解析估算，不是 GPU 实测，也不是完整服务端恢复时间或系统生命周期成本**。

复用七种条件的 252 个有备份配置，逐点核对前图的延迟、等待与帕累托集合；新增同条件的 252 个无备份解析配置。无备份事件流水另外以逐批时长和边界等待求和交叉检查，并核对所有对应批的时间平移。主图的七个统一基线从这 252 个无备份配置中选择；不是额外的统计样本。没有独立重复试验、置信区间或新 GPU 实验。
