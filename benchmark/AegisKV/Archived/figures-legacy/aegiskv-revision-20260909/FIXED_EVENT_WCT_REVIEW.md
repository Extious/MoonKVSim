# Fixed added-fault WCT figure review

The figure answers the descriptive question: for the same seven displayed Workflow IDs, how does adding the fixed GPU 2 fault at 180 s change WCT relative to the schedule containing only the GPU 0 fault at 60 s?

Both schedules use 120 s downtime per fault. The ordinate is each system's own `WCT(K2) − WCT(K1)` in seconds. It is not a contrast against no failure. Data are uncalibrated simulations retaining the frozen source-v3 algorithm with the separately derived external-clock fault protocol. Six existing executions are reused; this renderer launches none.

The seven Workflow IDs are the union of directly active/queued victims observed in the three systems at the added event. This is a post-treatment descriptive group, not a prespecified causal cohort or the main all-workflow population. All three systems show the same seven IDs, including the cases in which that system had no directly affected request. The separately prepared all-160 pairing table must remain available. Equal intervention time and physical GPU do not imply equal actual victims or equal lost KV. This plot cannot on its own establish a Peer HBM restoration benefit.
