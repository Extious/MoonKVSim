\subsection{KV Master: Backup Decisions}
\label{sec:kv-placement}
\label{sec:kv-master}

KV Master (3) chooses backup timing, the recovery tier (recomputation,
DRAM, or Peer HBM), and historical blocks eligible for Peer residency.
It uses the Recovery Manager's fixed target assignment and the Adapter's
window settings for checkpoint interval, capacity, and common layer
depth (\S\ref{sec:kv-runtime}).

\paragraph{Decision triggers.}
The Master establishes a policy at arrival, offers sealed state at
prefill completion, and reviews an active request after each additional
$Z$ generated tokens. The Adapter sets $Z$ each control window. Sealing
updates eligibility; it does not by itself trigger every backup.
Significant slack or DAG changes and window updates can refresh policy
earlier. Completion releases that request's Peer references, preserving
shared references; unchanged decisions produce no new transfer.
Hot-block statistics use the preceding 512 decoding steps, independently
of the checkpoint interval and wall-clock control window.

\paragraph{Choose protection tiers.}
Let $T_{\mathrm{rc}}$ be historical-prefix recomputation cost,
$T_{\mathrm{rp}}$ known-tail replay cost, and $W_0$ exposed DRAM-loading
wait without Peer residency. Detection, rerouting, and readmission
contribute $R_{\mathrm{floor}}$. The Master uses
\begin{equation}
\begin{aligned}
 R_{\mathrm{base}}&=R_{\mathrm{floor}}+T_{\mathrm{rp}},\\
 R_R&=R_{\mathrm{base}}+T_{\mathrm{rc}},\quad
 R_D=R_{\mathrm{base}}+W_0.
\end{aligned}
\label{eq:recovery-base}
\end{equation}
Costs are calibrated by model, context, tail length, hardware, and
representative concurrency; \S\ref{sec:kv-runtime} uses these recovery profiles.
Tier \emph{R} requires no backup when $\sigma_r\ge R_R$;
tier \emph{D} retains DRAM when $R_D\le\sigma_r<R_R$;
tier \emph{P} retains DRAM and requests Peer protection otherwise.
Tier changes use 20\% hysteresis around these nominal boundaries.
Peer is an additional fast copy, with actual residency reported by
the Adapter. A tier-P request with no Peer grant retains DRAM recovery.
Slack orders requests competing for Peer; it does not scale their
per-layer hot sets or impose a serial retry order.

\paragraph{Define and rank protection objects.}
A protection object is a \emph{(layer, block)} containing all KV heads;
the profiled selectors use 64-token blocks. Sealing makes a full block
eligible for copying; the commit frontier determines the prefix that
survives failure. Known uncommitted tokens, including sealed but
uncommitted blocks, are replayed without resampling.

The historical blocks needed by a length-$n$ replay form the union
$U_l(n)=\bigcup_{q=1}^{n}\bigcup_g S_{l,q,g}$, where $S_{l,q,g}$ is the
native selector output. Repeated reads count once. A fixed preload
fraction $h$ is configured for the chosen model and sparse-attention
method using replay profiles; it is not the selector's instantaneous
Top-$k$ fraction or a guaranteed hit rate. At time $\tau$, let $n_r(\tau)$
be request $r$'s sealed historical block count per layer. The Master uses
\begin{equation}
 K_r(\tau)=\lceil h n_r(\tau)\rceil
 \label{eq:hot-block-count}
\end{equation}
slots in each layer, reserving mandatory sealed sink/window blocks
\emph{within} that quota; the configured quota must accommodate them.
Remaining slots follow actual selection counts, breaking ties by recency.
An optional block leaves the candidate set after two successive decoding
windows outside the top set. A replacement needs fresh admission if
the old replica still has a request reference; changing hotness alone
does not free its physical slot.

The Adapter uses one $L$ for all requests in each control window. For
uniform layer layouts, a request's candidate Peer set therefore has
$LK_r(\tau)$ layer-block objects, plus required selector state.
Sealing changes the quota only when the rounded count changes; it does
not trigger a new layer-depth decision. Hot-block identities can change
without increasing the candidate quota. D and P retain these sets as
preload hints; P requests offer the leading $L$ sets for Peer admission.
Actual coverage can be partial, while previously referenced copies
remain charged until safe release.

Algorithm~\ref{alg:placement} emits policy, not readable replicas.
It shows a full refresh; a token-interval event updates only the affected
request's desired policy and retains the others.
\textsc{Tier} applies hysteresis to an existing tier and uses the nominal
thresholds at arrival. Sorting costs $O(n\log n)$ for $n$ requests;
physical shared objects are deduplicated during allocation. Adapters
reconcile changed policy with committed copies and return their actual
residency, commit status, and loading estimates for the next policy refresh.
