# Abstract

多智能体应用通过相互依赖的 LLM 请求完成任务，并在交互过程中积累长上下文。KV 状态丢失后的恢复代价可能很高，但它对工作流完成时间的影响取决于各请求的延迟容忍度。AegisKV 是一个基于多层存储的工作流感知 KV 容错框架：利用依赖关系和剩余执行时间估计计算请求 Slack，再结合恢复代价选择保护层级并分配有限的备份资源。在请求内部，稀疏注意力访问与逐层执行顺序指导 KV Block 放置和恢复，将有限 Peer HBM 用于减少影响工作流完成的恢复等待。

设计区分故障后 KV 的可恢复性与有限 Peer HBM 驻留，允许所属请求更新热集，并在容量收缩时安全降级至 DRAM，同时保持原生稀疏选择语义。原生选择轨迹，以及采用实测 forward 时间和假设传输带宽的流水线模型，为这些机制提供依据；端到端工作流收益和正常服务开销仍待评估。
