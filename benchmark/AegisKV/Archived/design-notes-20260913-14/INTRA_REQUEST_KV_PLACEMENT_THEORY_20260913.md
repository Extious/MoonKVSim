**请求内 KV 的两个放置维度：层次顺序与原生稀疏访问**

2026-09-13。本文按用户要求只进行理论分析，不运行实验、不改变执行器或租金实现。下述命题是针对明确恢复模型的推导，不是已有系统的性能结论。文献引用用于说明模型机制；最优性与收益公式为本文条件分析。

固定 Router 指定的接管 DP，备份 Peer 就是该 DP。Peer HBM 中已提交且布局兼容的 KV 可直接使用。其他有效备份留在故障域之外可访问的 DRAM Pool，恢复时经历相应网络路径及 H2D。对照放置具有相同有效恢复覆盖和新鲜度，因此 HBM 的附加价值来自减少装入等待；两种介质上的有效副本都能避免相同历史状态的重建。

只备份历史 KV 并不等于保存了未完成 token 的层间激活。以下假设重试所需 token 的前向从第一层开始，复用 M 个历史 token 的 KV，处理 N 个待前向 token。如果另有可恢复的中间激活检查点，“前几层”应改为恢复入口之后最早消费状态的层。

**层次维度使数据的消费期限不同。**

Dense attention 的每一层都需要对应的有效历史 KV，但各层按前向依赖依次执行。第一层历史 KV 几乎马上会被消费，后续层的消费发生得更晚。驻留前层能够提前启动计算，并把这段计算时间用于装入后层；驻留后层通常无法弥补第一层尚未就绪造成的启动等待。

这一机制与 [CachedAttention §3.2.1、Figure 6–7](https://www.usenix.org/system/files/atc24-gao-bin-cost.pdf#page=6) 的逐层预加载及缓冲分析一致。这里研究的是在固定接管端提前放置哪些备份，不将逐层 overlap 本身宣称为新机制。

设 S 为初始驻留在 HBM 的整层集合，第 l 层的计算耗时为 C_l，从 DRAM 装入该层全部历史 KV 的耗时为 D_l。先采用以下简化条件：复制从时间零开始，单一复制流按层序尽早复制所有未驻留层；计算与复制独立；目的空间足够；每层计算前等待该层 KV 完整就绪。于是：

\[
A_l(S)=
\begin{cases}
0,&l\in S,\\
\displaystyle\sum_{j\le l,\ j\notin S}D_j,&l\notin S,
\end{cases}
\qquad
F_l(S)=\max\{F_{l-1}(S),A_l(S)\}+C_l,\quad F_0=0.
\]

每层暴露的等待为 w_l=[A_l-F_{l-1}]_+。在这一串行计算模型下，T(S)=F_L=Σ_l C_l+Σ_l w_l。复制耗时没有再与计算时间直接相加。

这一递推反映两个同时发生的效应：把前层 KV 放入 HBM 会使其更早可用；不再复制它，也会让复制队列中的后续层更早到达。每增加一层后的价值应从新时间线计算，不能给每层永久附上其全部 D_l。

**命题一：在等层容量和等层复制耗时的上述模型内，前 k 层是一种最优整层放置。**

假定每层历史 KV 字节数相同，D_l=D，C_l≥0 且不受放置改变。设任意 k 层驻留方案中，未驻留层的层号依次为 i_1,…,i_(L-k)。展开递推得到：

\[
T(S)=\max\left\{\sum_{l=1}^{L}C_l,
\max_{1\le m\le L-k}\left(mD+\sum_{l=i_m}^{L}C_l\right)\right\}.
\]

对于任意 k 层驻留方案，都有 i_m≤k+m。驻留前 k 层时，恰好 i_m=k+m。因为 C_l 非负，所有尾部计算和 Σ_(l=i_m)^L C_l 都在前 k 层方案下最小，因此其 T 不大于任何其他 k 层方案。k=L 时没有传输项，T=Σ C_l。

这个结论允许各层计算耗时不同，但要求相同层容量、相同复制耗时及上述共同调度和依赖。它不覆盖有限缓冲、异构层 KV 尺寸、不同网络路径、计算复制争用、细粒度算子流水及未知的动态稀疏选块。存在同样快的其他放置，也不意味着逐层边际收益严格递减。

**等时模型进一步给出应驻留多少层。**

若 C_l=C，定义全部放在 DRAM 时的暴露等待：

\[
W_0=D+(L-1)[D-C]_+.
\]

驻留前 k 层时：

\[
T(k)=LC+[W_0-kD]_+,
\qquad
T(0)-T(k)=\min\{kD,W_0\}.
\]

新增第 k 层的收益为 Δ_k=min{D,[W_0-(k-1)D]_+}。D>0 时，消除上述全部装入等待所需的最少前层数为 k*=ceil(W_0/D)，且 k*≤L；实际仍受备份预算约束。D=0 时没有该加载收益。

- C≥D 时，驻留首层即可消除全部 W_0=D；HBM 只需容纳 1/L 的历史主 KV。但是省下的是一次 D，不能自动外推为很大的总请求或 WCT 改善。
- C<D 时，后续层可能持续等待传输，提前驻留更多层提供额外缓冲。C/D 越低，所需 k* 越大；当 C 接近零时，可能需要接近全量驻留。
- C 必须是恢复执行中实际一批 N 个 token 的前向时间，包含对 M 个历史 token 的 attention。不能拿已经被 KV 备份避免的历史 Prefill 重算时间充当 overlap 窗口。

上述闭式采用从时间零连续提前预取。若执行器严格只预取下一层，k≥1 时收益变成 D+(k-1)[D-C]_+，不能混用两种规则。

真实算子若可在历史 KV 到达前完成 QKV 投影，可将每层划分为前置计算 P_l 与等待后计算 Q_l，使用 F_l=max{F_(l-1)+P_l,A_l}+Q_l。若接管排队期间就能提前装入 DRAM 数据，也应把该提前量算进去。由此第一层的加载也可能已被隐藏，不能默认 HBM 总能省下完整 D_1。

分层放置由此得到的理论规则是：在上述整层模型里优先向前配置驻留容量，达到等待饱和点后将后层留在 DRAM；同层等路径、等大小 chunk 不必有不同的语义排序。恢复工作集和预取空间另外计入，少量初始备份不等于恢复全过程只需少量显存。

**同样的前向优先还可以扩展到部分层的 chunk。**

若进一步采用统一带宽 β、忽略固定复制开销、允许按字节或等大小 chunk 拆分，每层主 KV 大小为 s_l，初始驻留量为 x_l，且总预算为 H，那么按层序复制时的累计复制完成时刻为：

\[
G_l=\frac{\sum_{j\le l}(s_j-x_j)}{\beta}.
\]

在整层消费门的模型里仍可用 F_l=max{F_(l-1),G_l}+C_l。某层完全驻留时，G_l=G_(l-1)≤F_(l-1)，这个累计时刻不会引入虚假的等待。

从第一层开始依次填充 HBM 容量，能够对每个层前缀同时达到 Σ_(j≤l)x_j=min{H,Σ_(j≤l)s_j}，从而同时最小化所有 G_l，也就不会晚于任何其他同预算放置的完成时间。这一连续分配结论允许 s_l 不同，但依赖统一的线性传输成本及其余流水假设。

因此不足以放满下一层的剩余 HBM 也可以保存该层的一部分 chunk，减少必须搬运的字节；这些同层 chunk 按字节等价。不能据此推广到固定启动成本显著、块大小不一且不可分、异构链路或未知稀疏需求的情况。若层大小、计算时间分别均为 s、C，D=s/β，则前向连续分配的等待收益为 min{H/β,W_0}；整层公式是 H=ks 的特例。

**稀疏维度使数据的访问必要性不同。**

把一个物理历史 KV 块写成 b=(layer, KV group, physical block)。对恢复中的 query 事件 e，令 z_(e,b) 表示原生注意力是否实际需要该块。需要集合之外的完整主 KV 可以暂留 DRAM；选中的 DRAM 块则必须在相应 attention 消费前装入。目标是保持原生稀疏模型的计算语义。

例如 [NSA §3.3.2](https://arxiv.org/html/2502.11089v1#S3.SS3.SSS2) 从压缩注意力分数构造选块分数，聚合同一 GQA 组的查询头信息，再选出 top-n 块。它还包含压缩与窗口分支。因此“吸收较多注意力”可以影响是否被选中，但不是一个适用于所有原生稀疏模型的直接 I/O 价格。

应区分三件事：

| 量 | 所表达的含义 | 对 HBM 放置的作用 |
|---|---|---|
| attention mass / selector score | 对输出的权重或原生选块排名 | 可以用于推断需求，但不直接等于搬运收益 |
| z_(e,b) 或窗口内被选中概率 | 是否需要读取该物理块 | 决定这笔 DRAM 加载是否会发生 |
| 数据到达与消费期限的关系 | 这笔加载是否阻塞恢复 | 决定 HBM 能否减少完成时间 |

**一个反例说明仅按注意力质量分配 HBM 不充分。**

假定某个原生稀疏 query 必须读 A、B 两个等大小的块，其归一化注意力质量为 0.99 与 0.01；每个块的 DRAM 加载均耗时 D，只有一个块能预驻留，并且两块都必须就绪才能完成这次 attention。驻留 A 或驻留 B 都剩一次 D 的加载。即使 A 对输出影响更大，二者在这个状态下的备份加速价值仍相同。

同样，若一次 attention 固定选 m 个等大小块，在全部加载暴露且复制串行的简化模型中，预驻留其中 h 个后，剩余加载为 (m-h)D。收益取决于选中集合的物理命中，而不是命中块的注意力质量之和。若跳过仍被原生选择器选中的低分块，那是额外的近似恢复，不能由 HBM/DRAM 的精确分层自然推出。

**稀疏性形成长期备份优先级，需要分析整个恢复窗口的需求。**

设 W 覆盖本次重试中需要计费的冷加载过程，定义 U_W 为 W 中被选中历史物理块的并集。不能只截到首个输出，将稍后的 Decode 冷加载排除在请求完成延迟之外。

如果 HBM 中的集合 H 覆盖 U_W，且所需辅助状态就绪，则窗口内不再需要为这些历史主 KV 从 DRAM 加载。其余主 KV 可以继续留在 DRAM。这是“少量 KV 带来大量备份收益”的一个明确充分条件：小的 H 覆盖了关键恢复窗口的实际需求，而不仅是某个 query 的大部分注意力质量。

原生稀疏并不保证 U_W 很小。[NSA §3.4](https://arxiv.org/html/2502.11089v1#S3.SS4) 明确讨论同一 query tile 的不同 query 可以需要不相交的 KV 块。层、KV 组、query 之间的物理需求必须分别合并，不能以单 query 稀疏率替代整个请求的备份覆盖率。

进一步，假定按需加载、没有无关推测性加载，且加载后的历史块在 W 内不被逐出。令：

\[
p_b=\Pr(b\in U_W\mid\mathcal I_{\rm before\ failure}).
\]

则初始 HBM 集合 S 对应的期望历史主 KV 加载字节为：

\[
\mathbb E[V_{\rm DRAM}(S)]=\sum_{b\notin S}p_b\,s_b,
\]

其中 s_b 是实际传输字节。这个等式只依赖期望的线性性，不要求 query 或块选择相互独立。

若再假定每次必要加载都串行且完全阻塞，块传输耗时为 d_b，那么驻留 b 的期望节省为 p_b d_b，单位 HBM 优先级为 p_b d_b/s_b。等大小、等传输耗时情况下，优先放 p_b 大的块。这是“热点优先”的条件理论依据。

它不是累计访问次数乘 d_b：同一块被选择一百次，如果第一次装入后始终驻留，通常也只产生一次 DRAM 装入。若窗口内所有块最终都要读，p_b 都接近一，访问频次本身就不再区分首次加载字节收益，需进一步比较其消费期限和可预取程度。

**动态选块还会改变最早能够发起预取的时间。**

对需要的块 b，记：

- u_b：消费者的其他依赖已经就绪、希望开始使用它的时刻；
- r_b：有足够信息确定或可靠预测要取该块、能够发起预取的最早时刻；
- d_b：其加载耗时。

在无复制排队的单依赖模型中，A_b=r_b+d_b，迟到量为 [r_b+d_b-u_b]_+。多个块可能共享同一等待区间；这些迟到量不能直接相加成请求关键路径时间。

Dense 后层的历史需求通常从恢复起点就确定，r_b 可以很早，前层计算提供较长的 u_b-r_b。原生动态稀疏选择则可能要等该层 Query 及选择器完成后才确定块索引，此时即使层号靠后，r_b 仍可能接近 u_b。后层并不自动拥有可用于准确预取的长窗口。

因此，把可预测的后层热点提前备份到 HBM，可能消除“选块后才发现必须加载”的等待。故障前已执行且需要重放的 query，如果已保存兼容的选块记录，可以利用记录；尚未执行的 query 只能使用当时可获得的信息进行预测。历史 score 不能无条件视作未来选择。HBM 放置不应反过来限制原生选择器只能从 HBM 中选块。

必需的压缩 KV、indexer、选择器状态、固定窗口及页面映射也属于恢复依赖。若必须先加载辅助状态才能选出热块，主 KV 命中仍可能被辅助状态阻塞；这些状态应作为同一恢复计划中的对象计费。

此外，数学上的稀疏掩码不自动提供跨 DRAM/HBM 按块取数。以上放置收益要求执行路径能够根据索引按需加载或预取，并让已就绪的数据被消费。如果执行器先把全层历史 KV 全部搬入 HBM 才启动稀疏算子，那么稀疏性本身不会减少这一步的装入量。

**两个维度在同一个 (layer, block) 空间内共同决定放置。**

| 块的特征 | 理论放置倾向 | 原因 |
|---|---|---|
| 前层，恢复时确定需要，来不及预取 | Peer HBM 优先 | 消费早且加载会暴露 |
| 前层，被原生策略排除 | DRAM | 无需因层号早而加载该主 KV |
| 后层，高概率需要，选块后才可加载 | Peer HBM 有价值 | 动态选择缩短了实际预取窗口 |
| 后层，需求已知且能够提前加载完成 | DRAM 可以满足 | 所需数据能够按时到达 |
| 很少进入恢复需求集合 | DRAM | 提前占用 HBM 的利用机会少 |
| 解锁选块或消费的辅助状态 | 根据依赖期限优先就绪 | 主 KV 已驻留也无法替代缺失的控制或压缩状态 |

这两个维度不适合简单相加为“层号倒数 + attention score”。层次主要影响消费期限，稀疏策略影响需求集合及其揭示时间；二者共同决定哪些加载会暴露。

在一般流水、共享依赖和竞争情形下，可统一写成集合相关的理论价值：

\[
v(b\mid S)=\frac{\mathbb E[R(S)-R(S\cup\{b\})\mid\mathcal I_{\rm before\ failure}]}{s_b}.
\]

R 是相同逻辑状态相对无故障执行的额外延迟，比较保持有效覆盖不变。Dense 层组和原生 sparse 物理块只是不同候选对象；对于不可独立恢复的对象，应按合法依赖组估值。一般情况下不能把独立算出的单块价值相加并声称全局最优。

进入请求间分配时，再用现有 Slack 将 R 的下降转换为 Workflow 损失代理的下降。租金接收由这些机制产生的价值，负责持续占用与在线维护；原始 attention score 或固定层号本身没有必要直接成为租金信用。

可用于论文的两个条件动机是：**逐层执行使历史 KV 的消费期限不同，提前驻留前层可以用后续计算隐藏后层恢复传输；原生稀疏选择使历史 KV 的恢复需求不同，提前驻留会被需要且难以及时加载的少量块，可以避免为大量暂不需要的主 KV 占用 Peer HBM。** 两个命题都说明了成立条件与放置方向，不预设所有恢复状态都存在显著收益。
