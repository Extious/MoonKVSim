# 请求内 KV 放置的 Motivation 与优先级定义

2026-09-13。本轮延续清理前中断的理论分析，交付四张可复算图。没有运行模型、故障实验或新的性能模拟。图中的时间来自结构 FLOP 数与显式假设的有效速率；不能用作硬件性能或 Workflow completion time（WCT）的实测结论。

建议论文采用的主张是：**相同有效备份覆盖下，请求内 KV 的价值是它在固定接管 DP 上预先就绪后，能够消除多少恢复关键路径等待。层序影响消费时间；原生稀疏策略影响需求集合及其可知时间。** 租金负责维护有限容量，接收这一价值作为输入。

分层路线有明确的条件推导。稀疏路线必须区分固定窗口等结构性需求与内容相关的动态选块：前者可以直接分析；后者的集中性不能仅从“原生稀疏”推出。

## 1. 冻结恢复状态，先分开覆盖与驻留

Router 预先固定 Retry DP，备份 Peer 就是接管 DP。故障域之外仍有效的备份覆盖前 M 个历史 token；其中前 k 层在 Peer HBM，其余在 DRAM Pool。故障发生时逻辑进度为 M+N，后 N 个已计算 token 的 KV 尚未提交，必须重放。

本轮 N 专指这段丢失状态的已知 token 序列。Prefill 输入或已经可靠保存的生成 token ID 可以用于重放；没有可靠输出记录时，还要解决生成状态和输出一致性，不能默认可直接批量重放。故障时未完成的层间激活也没有自动保存在 KV 副本中。

图从接管执行器可开始恢复时计时：权重、路由元数据已就绪；所有 DRAM 主 KV 从此时可开始预取。终点是这 N 个 token 完成最后一层前向。故障检测、接管排队、最后的输出投影及之后的生成不在该区间中。

- **M 决定避免了多少历史状态重建。** 放置对照保持 M、新鲜度、KV 格式、精度和恢复目标相同。
- **k 决定还会暴露多少装入等待。** Peer HBM 中可直接使用；DRAM 的有效副本同样避免历史重算，但要经过实际恢复路径装入 HBM。
- 少量备份容量不等于恢复全过程只需少量显存。本文连续预取模型允许接管后为恢复工作集分配更多空间。

同覆盖、新鲜度的比较不要求 P2P 备份一定比 D2H 快：已经提交到接管端的 HBM 副本，其价值来自恢复时少一次装入等待。正常备份速度、流量和对前台计算的干扰仍要计入最终净收益。

## 2. 从 M、N、模型和硬件推导驻留深度

### 2.1 实际要比较的两笔成本

若第 l 层、当前分片保存 h_KV 个 KV 头，每头 K/V 维度分别为 d_K、d_V，每个元素 b 字节，其历史状态大小为：

\[
s_l=M\,h_{KV,l}(d_{K,l}+d_{V,l})b_l.
\]

这里使用实际分片的 KV 头数；不能以 Query 头数代替，也不能在 KV 头复制时机械除以 TP。传输时间为实际路径函数 D_l(s_l)，在线性近似下写成：

\[
D_l=\alpha_l+s_l/\beta_l.
\]

β 是 DRAM Pool 到接管端可消费布局的有效速率。远端 DRAM 若还要经过网络、主机 staging、解包或格式转换，必须计入这些阶段；网络和 H2D 是流水还是串行会改变 D_l。本文数字示例采用 α=0、β=25 GB/s，GB/s 按十进制换算。

C_l(N|M) 是第 l 层实际重放 N 个 token 的前向时间，包括投影、对已有历史及因果后缀的 attention、MLP 和必要的其他算子。已经由备份避免的 M 个 token 的前向计算不能再充当 overlap 窗口。

Qwen3-8B 的本轮结构示例为 36 层、隐藏维度 4096、MLP 中间维度 12288、32 个 Query 头、8 个 KV 头、head_dim=128、BF16、TP=1。来源为 [Qwen 官方配置](https://huggingface.co/Qwen/Qwen3-8B/raw/main/config.json)。因此每 token、每层主 KV 是 4096 字节。

该结构每层线性权重计数为 P_linear=192,937,984。采用乘加计 2 FLOPs、忽略归一化和 softmax 等小算子的示例计算量：

\[
F(N|M)=2NP_{linear}+4h_Qd\left(MN+\frac{N(N+1)}2\right),
\qquad C\approx F/P_{effective}.
\]

图中 P_effective=100 TFLOP/s 是固定假设，**不是某张 GPU 的实测或标称性能**。实际 C 还受 batch、HBM 读权重、kernel、MoE 路由、跨卡通信和并行复制干扰影响，尤其不能把此固定有效算力近似推广到单 token Decode。最终系统应替换为匹配形状和并发状态的时间估计。

### 2.2 恢复时间线与“前 k 层”的依据

假设单一复制流从 t=0 按层序连续提前装入，计算与复制能够并行、互不干扰、预取空间充足；每层在完整历史 KV 就绪之后开始计算。初始 HBM 集合为 S：

\[
A_l(S)=\begin{cases}
0,&l\in S,\\
\sum_{j\le l,j\notin S}D_j,&l\notin S,
\end{cases}
\quad F_l=\max(F_{l-1},A_l)+C_l,
\quad w_l=[A_l-F_{l-1}]_+.
\]

因此 T=F_L=ΣC_l+Σw_l。H2D 中与计算重叠的部分不能再叠加到总时延。

在**等层 KV 大小、等层复制耗时、上述共同调度**下，前 k 层是一种最优的整层放置；允许 C_l 不同。证明和可按字节拆分的扩展见[完整理论](INTRA_REQUEST_KV_PLACEMENT_THEORY_20260913.md)。这里的层号优先来自恢复依赖，不是语义重要性。

进一步令 C_l=C、D_l=D>0，定义全 DRAM 基线的暴露等待：

\[
W_0=D+(L-1)[D-C]_+.
\]

前 k 层驻留时：

\[
T(k)=LC+[W_0-kD]_+,\qquad
\Delta T(k)=\min(kD,W_0),\qquad
k_{sat}=\left\lceil W_0/D\right\rceil.
\]

第 k 层的增量收益为 Δ_k=min(D,[W_0−(k−1)D]_+)。容量不足时，k≤floor(H/s)；无需为了达到 k_sat 强占所有其他请求的 HBM。如果可以按等价小块填充下一层，未凑满一层的容量也可减少剩余传输字节。

“少量 KV 有较大收益”存在两个不同分母：

1. 少量 KV 消除了多少**可避免的装入等待**：ΔT/W_0。
2. 实际恢复区间缩短了多少：ΔT/T(0)。即使第一项为 100%，第二项仍可能很小。

以下固定 M=32768、β=25 GB/s、有效算力假设不变，仅改变丢失的 N。每层历史 KV 为 128 MiB，全部历史为 4608 MiB。统一放前 6 层需要 768 MiB，即历史主 KV 的 16.67%。

| 丢失 N | 每层 C（ms） | 每层 D（ms） | k_sat | T(0) → T(6)（ms） | 节省（ms） | 消除的装入等待 | 恢复区间缩短 |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 128 | 1.182 | 5.369 | 29 | 194.46 → 162.24 | 32.21 | 21.21% | 16.57% |

### 2.3 各因素具体如何改变决策

| 因素 | 对放置的影响 | 限定 |
|---|---|---|
| 同 N、M 下 C 增大 | 后层传输更容易被隐藏，k_sat 通常减少 | 不表示让计算更慢有利；总恢复时间可能增加 |
| 有效 β 增大 | D 降低，通常更少前层即可饱和 | 单次条件下可节省的绝对 H2D 时间也可能减少 |
| M 增大 | 历史 KV 字节线性增加；MN attention 也增加 | 两笔成本同时变；不能只扩大 D 而固定 C |
| N 增大 | 实际重放计算增加，通常提供更长 overlap 窗口 | 丢失更多 KV 本身仍有代价，不应故意降低备份新鲜度 |
| h_KV、KV 精度或物理打包改变 | 改变 s_l、D_l 和每层驻留成本 | Query 头数与 KV 头数不能混用 |
| 原生稀疏计算 | 可能减少 attention 计算，也可能减少要加载的主 KV | 计算稀疏率与整窗物理需求并集比例不同，见第 3 节 |
| 单次故障概率提高 | 相同驻留的期望收益提高，可能值得给请求更多容量 | 固定 M、N、硬件时，不改变条件下的 ΔT 或 k_sat |
| 排队期间即可准确预取 | 原本暴露的早期装入可能已经完成 | 不能把这段已有预取收益再记给 Peer HBM |
| 有限预取缓冲、不同布局或资源争用 | 改变复制释放时间和 C/D，需重算事件图 | 闭式与前层最优性的前提可能不成立 |

若只能“计算第 l 层时预取第 l+1 层”，就不能使用上述 t=0 连续预取公式。类似地，若 QKV 投影能够先执行，应使用 F_l=max(F_(l−1)+P_l,A_l)+Q_l，C_l=P_l+Q_l；首层 H2D 的一部分也可能被自身前置计算隐藏。

[CachedAttention §3.2.1、Figure 6–7](https://www.usenix.org/system/files/atc24-gao-bin-cost.pdf#page=5) 已讨论逐层加载、启动空隙和预取缓冲。论文应将创新集中于故障 WCT 目标下的备份分配及在线维护，不把 overlap 本身作为新贡献。

## 3. 原生稀疏：什么可以理论证明，什么仍缺证据

### 3.1 先定义物理对象、访问率与首次加载

备份对象应写成 `(request, layer, KV-group/shard, branch, physical-chunk)`。原生选择单位、kernel tile 和物理传输块不一定相同；不同层的同一 token 不是同一个 KV 对象。独立压缩/窗口分支的状态也不能默认与选择分支共用同一 KV。

对恢复事件 e 和物理块 b，定义 z_(e,b)=1 表示该事件确实需要这个块。令 f_b=Σ_e z_(e,b)，U_W={b: f_b>0}。

- attention mass 是加权贡献，f_b 是需求次数，二者都不是首次 H2D 次数。
- 加载后不逐出时，一个历史块在窗口 W 内至多产生一次必要冷加载。
- ρ_pair 表示实际执行的 Query–KV 对相对 dense 的比例；u_l=Σ_(b∈U_W,l)s_b/Σ_(b∈history,l)s_b 表示物理历史需求并集比例。二者通常不相等。

在简化模型中，稀疏计算近似影响 `C_linear + C_attention(ρ_pair) + C_selector`；实际搬运则由物理并集、辅助状态和调度决定。若后缀 Query 各自只选很少块，但合起来遍历了历史，u_l 仍可能接近 1；C 变短而 D 没变，后层传输反而更难隐藏。不能直接把 Qwen3-8B 的 FLOP 或 KV 字节乘一个比例，就称作原生稀疏模型结果。

单层单组中，若每个 Query 选择 B 块中的 m 块，对 N 个 Query 有：

\[
m\le |U_W|\le\min(B,Nm).
\]

这个范围已足以说明：**单 Query 稀疏率 m/B 不能确定整窗工作集。** 如额外假设每个 Query 独立、均匀选择，则 E|U_W|=B[1−(1−m/B)^N]；这只是一个分布假设，不是 NSA 的实际选择规律。

![同稀疏率但不同恢复工作集的构造反例](/home/comp/zhanzhao/MoonKVSim/output/pdf/kv-motivation-20260913/sparse-window-counterexample.png)

图 3：两组构造选择，单层、单 KV 组、16 个 Query、32 个等大小历史块，每个 Query 都选 4 块。左例反复选择相同四块；右例覆盖全部三十二块。HBM 都预放四个会被需要的块，按需加载且不逐出时，剩余首次加载分别为 0 和 28。未声称这些选择来自某个训练好的模型；也没有把冷加载数量直接当作暴露等待。

### 3.2 一个不需要访问轨迹的成立情形：固定局部窗口

原生结构中固定的局部窗口可以直接给出请求内的需求差异。定义窗口包含当前 Query 前面的 w 个位置；Query 为 M+i，1≤i≤N。它对已有历史 [1,M] 的需求是 `[max(1,M+i−w), M]`，空区间不需要历史。

因此整个重放窗口对这条分支的旧历史需求并集最多为最后 min(M,w) 个 token。对历史位置 j：

\[
f_j=\min\{N,\max(0,w-M+j)\}.
\]

取 M=32768、N=w=512，则全部重复的窗口历史访问只发生在最后 512 个 token，即该分支历史的 1.5625%。按 64-token 物理块管理时，只有末尾八块会被需要，它们分别被 64、128、…、512 个 Query 访问。

![原生固定窗口的解析访问频次](/home/comp/zhanzhao/MoonKVSim/output/pdf/kv-motivation-20260913/native-window-structural-example.png)

图 4：根据固定窗口定义逐 Query 推导，不来自模型运行。w=512 参考 NSA 论文中的窗口配置；M、N 和物理传输块大小是本例配置。上图给出全历史位置，后两图放大末尾物理块并计算其访问次数。

这里确实证明了“少部分历史 KV 承担该分支全部历史访问”。但是首个 Query 已需要八块：若它们首次到达期限、大小和加载路径相同，仅因第八块访问更多，不能认为它比第一块省更多首次加载时间。可以优先保护这个窗口依赖集合，再由实际暴露等待决定集合内或跨层的分配。

[NSA §3.2–3.4](https://arxiv.org/html/2502.11089v1#S3) 还包含压缩与动态选择分支。**1.5625% 不是全模型所需备份比例，也不证明只备份这些窗口 KV 即可恢复整个请求。** 其他分支或辅助状态迟到，仍会阻塞该层完成。

### 3.3 内容相关动态选块的证据边界

NSA 在同一 Query 的 GQA 组内聚合压缩注意力分数后选块；不同 Query 可能需要不同块。论文 §3.4 明确提到同一 Query block 内可能出现不相交的 KV 需求。[NSA 原文](https://arxiv.org/html/2502.11089v1#S3.SS4)

本轮还核对了一个容易误用的出处：**NSA Figure 8 / §6.2 的注意力图来自其 27B Full Attention 模型。** 它不能作为 NSA 恢复窗口中动态选块集中、或故障前可预测热点的证据。[Figure 8 与 §6.2](https://arxiv.org/html/2502.11089v1#S6.SS2)

因此当前可以写条件命题：“若较小且故障前可识别的主 KV 集合覆盖恢复关键窗口中难以及时加载的需求，则提前驻留能减少相应等待。” 不能写成已经观察到的通用事实：“原生稀疏模型中少量语义 KV 总能捕获大部分故障恢复收益。”

以后若已有访问记录，论文中真正要替换图 3 的数据应至少包括：同一请求、明确 M/N、逐层和 KV 组的 Query×物理块选择矩阵、按原始位置的访问次数、窗口需求并集，以及故障前确定的 HBM 集合的命中情况。统计窗口应覆盖实际计入重试延迟的冷加载；不能只截到首个输出而漏掉后续 Decode 等待。当前不启动模型测量。

### 3.4 备份优先级使用什么量

以故障前可得信息 I 为条件，定义 p_b=Pr(b∈U_W|I)。在按需加载、没有错误预取、加载后不逐出时：

\[
E[V_{DRAM}(S)]=\sum_{b\notin S}p_bs_b.
\]

若必要复制还恰好串行、全部暴露，驻留 b 的期望价值才简化为 p_bD_b，单位容量价值为 p_bD_b/s_b。通常还要知道：

- r_b：何时能够得知需求并发起正确预取；
- u_b：消费者的其他依赖就绪、希望使用该块的时刻；
- A_b：考虑队列、复制及解包后的实际到达时刻。

局部迟到量 [A_b−u_b]_+ 只能帮助定位等待；多个块可能共享同一个等待区间，不能简单相加。动态选块往往使后层 r_b 仍很晚，因而“后层一定有充足预取窗口”也不成立。

故障前已经计算过的 N 个 token 如有已提交、版本兼容的选块记录，可用作重放需求信息；其日志占用和提交成本也要计入。尚未执行的 Query 只能预测，不能使用未来轨迹挑选 HBM 块。最终选择器仍按原生语义选块，选到 DRAM 数据就加载，不能因为只保护了热点而改成只在 HBM 内选块。

## 4. 接回 Slack 与租金：只定义一种价值单位

令 S_r 是请求 r 已驻留集合，R_r(S_r) 是固定逻辑状态下、相对同样无故障推进的额外恢复延迟。通用的请求内边际量为：

\[
v_r(b\mid S_r)=\frac{E[R_r(S_r)-R_r(S_r\cup\{b\})\mid I]}{s_b}.
\]

在本轮分层模型里，它由每次新增驻留量后重算时间线得到；在原生稀疏模型里，它还包含真实需求、揭示时间和辅助依赖。具有共同依赖的对象应按合法组估价；独立单块分数一般不可加。

请求间再应用现有 Slack。若采用简化单支路代理，剩余 Slack 为 σ_r，额外延迟损失函数为 ℓ_r(R)=[R−σ_r]_+。一个暂定信用输入可以是：

\[
G_r(b\mid S_r)=p_r^{fail}\,
E[\ell_r(R_r(S_r))-\ell_r(R_r(S_r\cup\{b\}))\mid I].
\]

单位是持有窗口内的期望 Workflow 延迟减少；除以字节后用于容量比较。真实多支路同时受影响时，应替换为已有 DAG/Slack 机制对应的损失估计，不把单支路 max 公式宣称为精确 WCT。

若在长度 τ 的持有窗口中采用恒定 Poisson hazard λ、只核算首次故障事件，可取 p_fail=1−exp(−λτ)。同一请求、同一持有窗口的公共故障概率不改变请求内候选的条件排序；它会影响与正常维护开销及其他请求的比较。多次故障、随时间变化的 M/N 或备份策略对新鲜度的影响，需要更完整的期望模型。

对现有租金方案的修改方向：

1. **替换信用依据。** 已有 DRAM 覆盖时，不再把避免历史 Prefill 重算的完整收益重复记给 HBM；信用来自额外减少的恢复/WCT 损失。
2. **信用与当前集合相关。** 一次增删改变后续传输队列和边际收益；层深已经饱和时，应把容量留给其他仍有收益的请求。
3. **保留覆盖约束。** HBM 是唯一有效副本时，降级必须先保证所需 DRAM 提交；保持 M 的对照不能通过静默损失有效覆盖来实现。
4. **租金负责持有和调整。** Slack、M/N、目标端资源和需求预测变化时重估收益；是否调整驻留还应计入迁移与正常服务影响，避免反复搬动。
5. **分别评价价值与维护。** “前层/需求感知估值”回答该保护什么；“租金与滞回”回答在变化时如何稳定维护。理论估值不意味着原租金实现已经完成修改。

撤销已有驻留时，使用 `R(S\{b})−R(S)` 的当前损失；不能把“向 S 再添加已存在的 b”的零增益当作保留价值。若沿用现有 all-block-rent 账本，重估价值不自动返还已付租金或重发信用；所有仍占资源的已提交备份继续付租，Q 只控制安全淘汰资格。这里不改写原有 H 等账本语义。

第一版方法可采用分层前缀候选及真实恢复调度估值，将固定窗口/辅助状态作为原生模型扩展；内容相关动态热点保持条件性扩展，等待访问证据。论文的主要新意应落在固定接管与 Workflow Slack 约束下的跨请求、请求内联合分配。
