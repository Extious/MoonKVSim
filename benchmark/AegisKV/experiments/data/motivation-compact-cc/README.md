# 当前 Motivation 四分支实例与同配置实测成本

Figure 1(a) 是第 20 个四分支组，来自工作流 `631738ac31321409f3a8de750fd5cd0ea334`。A1–A4 的持续时间分别为 60.370 / 151.612 / 132.409 / 129.429 s，gap 为 91.242 s。这个组通过与 Figure 1(b) 相同的时间代理 fan-in 筛选；它不是该工作流的最大组（最大 gap 为 314.383 s），不能当作 ECDF 中某个点的直接展开。

固定选择规则仍在 `SELECTION.json`：四至五个分支、gap 在 100±15 s、最长分支不超过 250 s，并从全部分支都有活动 LLM 请求的时间区间中选取一个时刻。选择偏向可见的恢复影响，是说明性例子，不是随机故障样本。当前注入暂停的位置为 fork 后 29.452 s；实际依赖只由时序代理推断，计算假定所有分支都必须完成。

## Figure 2 当前成本来源

`recovery-costs-measured.json` 是当前图的权威成本与分支映射。Qwen2.5-7B-Instruct-1M、2×A100-PCIE-40GB、TP2、BF16、batch 1、SGLang 0.5.10rc0 和 MInference/DCA 执行配置，与 Figure 1(c) 作业 1517208 的模型/内核源码及配置哈希匹配。各历史长度来自 frozen trace 的 hash-block 数×64，测量使用固定合成文本，C=M+1；不是原 Claude prompt 或实际故障时 KV frontier 的测量。

前三个长度来自作业 1517915，最后一个长度来自 1517917。前者在最后一个长度收到提前终止信号；仅其已完整封存并校验的三个长度用于绘图，未完成点的部分计时保留在原始记录中但整组排除。每个绘图点都有一次完整预热后的三次计时；min–max 是计时范围，不是置信区间。不同分配之间的差异不包含在这一范围内。

在固定其他执行与队列后，分别把一个实测 Prefill 中位数 R 作为额外暂停插入该分支，WCT 增量按 `max(0,R−slack)` 计算，并独立通过推迟后的 join 复核。**只有 Prefill 延迟是实测，WCT 是计算的反事实。** 四行不能相加为一次共同故障损失。

完整协议和复现命令见 `../reuse-physical-qwen25-1m/MOTIVATION_EXPOSURE_PROTOCOL.md`。绘图使用 `experiments/scripts/paper/render_motivation_compact.py --only exposure`；它强制验证 measured mapping 和来源哈希，不能回退到静态成本。
