# 逐层窗口出现率预测：离线覆盖率分析

本分析回答：在每层约 40% 的固定 KV 容量下，使用历史窗口出现率和时间衰减选择 KV 块，能够覆盖后续 256 / 512 个 Query 所需的多少历史 KV？

结果：本次固定参数下没有出现跨模型的普遍改善。后续 256 Query 的所有层等权平均覆盖率为 NOSA-3B **67.97%**、MiniCPM4-8B **47.52%**、SeerAttention-Qwen3-8B **40.91%**。这是已有原生选择器轨迹的离线分析，没有进行新的 GPU forward、故障注入或恢复执行。

## 固定协议

| 项目 | 设置 |
|---|---|
| 数据 | 已有原生模型 PG19 轨迹，文档 10146、10321、10356；每文档一个 checkpoint |
| 模型层数 | NOSA-3B 32；MiniCPM4-8B 32；SeerAttention-Qwen3-8B 36 |
| 历史长度 | M = 32768 token |
| 物理对象 | 请求、层、64-token 块，包含该块的全部物理 KV heads |
| 每层配额 | K = 205 / 512 个历史块，即 40.0391% |
| 观察区间 | 过去 2048 个 Query：30721–32768，位置从 1 开始 |
| 256-Query 配置 | 8 个已完成的 256-Query 观察窗口，预测 32769–33024 |
| 512-Query 配置 | 4 个已完成的 512-Query 观察窗口，预测 32769–33280 |
| 时间衰减 | 最新窗口权重 1，再向前依次为 0.5、0.25…… |
| 必需块 | NOSA：1 个 sink + 16 个 local；MiniCPM4：1 + 32；Seer：无固定必需块 |
| 同分处理 | 优先较新的块位置 |
| 窗口内更新 | 无：选择在 checkpoint 时确定，整个目标窗口内保持不变 |

这些参数在查看本次结果前固定，没有搜索参数、根据目标窗口调参或分别拟合各层。它是讨论中的通用历史预测部分的一种具体实现，并非所有候选机制的最优结果。

对每个历史窗口，某块只要被任一 Query / group 选择，就记为出现一次。将窗口内的次数转成 0/1 后，再以时间衰减权重求加权平均。先保留必需块，然后按分数选择剩余块，直至总数达到 K。所有 head/group 的选择都映射到整层物理块，未按 head 分配备份。

两列的衰减半衰期都是一个观察窗口，因此分别对应 256 和 512 Query。它们比较的是两种匹配目标长度的配置，不能把两列差值完全解释为目标窗口变长的单独因果效应。

## 比较方法与统计口径

- `window_presence`：上述过去 2048 Query 的窗口出现率 + 衰减。
- `frequency_2048`：相同过去 2048 Query 的原生选择事件频率；这是图中的主要公平基线。
- `frequency_512`：此前只观察最后 512 Query 的原始频率方法；保留作为历史结果参照。
- `oracle`：预先知道目标窗口的需求，在相同必需块与每层配额约束下得到的上限，不能实际在线执行。

对一个文档的一层，覆盖率 = 选中且被未来窗口需要的历史块数 / 未来窗口需要的不同历史块数。重复读取只计一次，checkpoint 后才产生的 suffix KV 不在历史需求分母中。这不是逐次访问命中率，也不是注意力质量或恢复加速比例。

图中的每个层点先计算各文档该层的比率，再对三个文档取平均。图内标注和下表的 **macro** 先在每个文档内对所有层的覆盖率等权平均，再平均三个文档。另行保留的 **weighted** 先在每个文档内汇总所有层的命中块数与需求块数后相除，再平均三个文档。层是同一文档内的相关观测，不将 32/36 层冒充独立样本。

### 所有层等权平均覆盖率（macro，%）

| 模型 | 后续 Query | 窗口出现率 | 频率：过去 2048 | 原频率：过去 512 | 上限 |
|---|---:|---:|---:|---:|---:|
| NOSA-3B | 256 | 67.97 | 66.74 | 67.86 | 76.31 |
| NOSA-3B | 512 | 61.62 | 61.79 | 62.29 | 67.51 |
| MiniCPM4-8B | 256 | 47.52 | 47.59 | 47.77 | 49.45 |
| MiniCPM4-8B | 512 | 44.47 | 44.59 | 44.56 | 45.22 |
| SeerAttention-Qwen3-8B | 256 | 40.91 | 41.20 | 41.20 | 41.24 |
| SeerAttention-Qwen3-8B | 512 | 40.39 | 40.48 | 40.48 | 40.49 |

### 按需求块数加权覆盖率（weighted，%）

| 模型 | 后续 Query | 窗口出现率 | 频率：过去 2048 | 原频率：过去 512 | 上限 |
|---|---:|---:|---:|---:|---:|
| NOSA-3B | 256 | 64.63 | 63.49 | 64.52 | 72.41 |
| NOSA-3B | 512 | 58.21 | 58.45 | 58.90 | 63.41 |
| MiniCPM4-8B | 256 | 46.52 | 46.62 | 46.78 | 48.19 |
| MiniCPM4-8B | 512 | 43.98 | 44.11 | 44.08 | 44.66 |
| SeerAttention-Qwen3-8B | 256 | 40.85 | 41.13 | 41.13 | 41.17 |
| SeerAttention-Qwen3-8B | 512 | 40.37 | 40.46 | 40.47 | 40.47 |

NOSA 的 256-Query 配置比相同观察长度的频率方法提高 **1.23 个百分点**，但相对此前 512-Query 频率方法仅提高 **0.11 个百分点**。其他模型及 NOSA 的 512-Query 配置没有提高。保留全部负结果，不据此追加事后参数筛选。

MiniCPM4 和 Seer 的上限接近当前覆盖率，说明在本次“整层物理块、窗口内固定放置、不同需求块覆盖率、40% 配额”的约束下，仅改善排序无法获得 90% 等高覆盖率。该结论不否定动态补取、不同容量、较短窗口或隐藏传输等待的价值，也不直接说明恢复延迟收益大小。

## 数据来源与证据边界

原生轨迹位于 `experiments/native-sparse/20260915-nosa-3b`、`20260915` 和 `20260918-seer-qwen3`。本次分析对 300 个逐层轨迹及对应运行、配置文件核对 SHA-256，与 `design-insights/retry-kv-summary.json` 的来源清单及逐运行清单一致。具体记录见 `source-sha256.json`。

NOSA/MiniCPM4 使用记录下来的原生选择器输出。Seer 使用原生 64-Query / 64-key block mask，保留 query-block 粒度，未构造不存在的逐 token 选块。Seer 为已固定 checkpoint 与 gate 配置的实验版本，此处不代表其他 Seer 配置或所有稀疏注意力模型。

NOSA 的记录数组覆盖整个原始 forward，但独立的“选择器输出与 kernel mask 相等”检查仅覆盖零基区间 `[32256, 33280)`。本分析扩展使用更早保存的原生选择器输出，没有进行扩展区间的 mask 一致性复测，不能声称该检查也已覆盖全部 2048 个历史 Query。

两种预测目标的所有选块方案均在读取目标需求前由历史统计确定。分析还逐文档、逐层复现了旧 `retry-kv-z512/layers.csv` 中 256 / 512 Query 的需求数、原频率命中数和同约束上限。

这是三个复用 PG19 文档、每个文档一个 checkpoint 的诊断，未测量 Agent 工作负载、跨任务泛化、实际故障阶段分布、传输/计算重叠、备份开销或 WCT。未接入原生模型专属预测先验、在线参数校准或完整 KV Master。本目录是独立分析，不自动同步当前论文设计。
