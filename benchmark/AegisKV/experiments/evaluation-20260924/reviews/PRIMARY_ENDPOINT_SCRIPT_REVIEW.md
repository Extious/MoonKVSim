# Primary endpoint analysis and plotting: independent review

The current `analyze_primary_endpoints.py` and `plot_primary_endpoints.py` use the
correct target and endpoint definitions. No additional material arithmetic or
grouping defect was found. This is an independent artifact review; no simulator,
analysis function or plotting function was imported by the numerical checker.
The first message suggesting a missing `stratum` field was a reading error and
was withdrawn; both the source and existing CSV contain it.

Code evidence (paths relative to `experiments/scripts/current_design/`):

- `analyze_primary_endpoints.py:51–63` selects the failed Agent and invocation
  from the frozen job and requires exactly one matching **active** recovery row.
  It does not substitute an unrelated co-victim or a queued `history_restores` row.
- Lines52–56 restrict DAG successor testing to the target Workflow. A sink has
  no successor; this structural classification does not claim a critical path.
  The saved five identities are S1/N2/S3/N4/S5: three sinks and two non-sinks.
  Independent cross-policy/model/load identity checks confirm this mapping.
- Lines88–95 subtract the target Workflow's **own-policy F0** WCT from F1. The
  all-Workflow mean includes all62 Workflows in each matched run. It does not
  replace the target by the largest observed delay or discard negative values.
- Lines96–104 use failure-to-first-new-output latency, detection, retry queue and
  service separately. The runtime records latency as first_new_token minus
  failure_ns, and service as first_new_token minus admitted_ns
  (`current/runtime.py:1295–1299`). Its first post-recovery decode step is limited
  to one token (`runtime.py:1126–1127`); this endpoint is not EOS or full KV restore.
- Lines108–128 publish all-five, sink and non-sink strata with explicit counts.
  These are descriptive means over five fixed failure identities, reusing each
  policy's healthy run. They are not five independent physical repetitions.
- `plot_primary_endpoints.py:37–40,47–78` indexes every(model,load,policy,identity)
  row without outcome selection. It shows150 markers in six panels, including
  negative target penalties. The same five IDs are horizontally offset only to
  distinguish policies. Lines53–55 and79–84 retain zero and negative values and
  share each model's vertical scale. The plot does not fabricate confidence bands.

Failure-to-first-new-token includes detection, retry admission waiting, rebuilding
lost/replayed state, remaining normal prompt processing where applicable, and the
first new output step. It is a modeled user-visible recovery endpoint, not a
standalone transfer timer, the fault-induced increase over healthy first-token
latency, or a hardware measurement. The postfailure load field is the configured
arrival-load proxy scaled by surviving worker count, not measured utilization.
Negative Workflow ΔWCT values are retained scheduling outcomes; physical elapsed
failure-to-first-new-token time remains nonnegative.
