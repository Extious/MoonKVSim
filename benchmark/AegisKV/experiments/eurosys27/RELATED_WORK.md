# Related-work evidence and novelty boundary

Primary sources checked on 2026-09-20. The existing bibliography keys were reused where possible. This table describes documented mechanisms; it is not an experimental comparison. Performance numbers from other papers are not transplanted into AegisKV plots.

| Work | Verified mechanism | Boundary for this paper | Required fair comparison |
|---|---|---|---|
| [DéjàVu, ICML 2024](https://proceedings.mlr.press/v235/strati24a.html) | KV streaming for disaggregation, memory management and replicated-state fault recovery | KV replication itself is established | Same token log/frontier, amount of state, failure detector and survivor capacity |
| [GhostServe, MLSys 2026](https://proceedings.mlsys.org/paper_files/paper/2026/hash/d99e8e80a6c41e148db686918dd7eab3-Abstract-Conference.html) | Streaming KV protected with host parity via erasure coding | Coding/redundancy is different from workflow placement | Count parity memory, coding compute and checkpoint lag; distinguish replication vs coding |
| [RaidServe, MLSys 2026](https://proceedings.mlsys.org/paper_files/paper/2026/hash/507b4aacefe5325908e24f042617b741-Abstract-Conference.html) | Resilient TP serving with cyclic KV placement, hybrid attention and fine-grained load-aware routing | Irregular GPU availability/TP resilience is a different contribution | Evaluate only a topology and implementation supporting that recovery model |
| [LUMEN, 2026 preprint](https://arxiv.org/abs/2606.17787) | Coordinates checkpoint location, interrupted-request distribution and serving-capacity restoration | Load-aware failure routing is already studied | Apply the same recovery distribution to both cache policies before claiming placement benefit |
| [Mooncake, FAST 2025](https://www.usenix.org/conference/fast25/presentation/qin) | Disaggregated KV cache uses DRAM/SSD/NIC and cache-centric scheduling | DRAM/SSD hierarchy is not novel | Tuned native transfer, cache and admission configuration; same total bytes |
| [Mooncake SSD offload documentation](https://kvcache-ai.github.io/Mooncake/deployment/ssd/ssd-offload.html) | Pressure-driven memory offload to filesystem-backed local storage and retrieval fallback | Local disk storage does not automatically survive loss of its host | Declare placement/fault domains and persistence semantics |
| [CachedAttention, ATC 2024](https://www.usenix.org/conference/atc24/presentation/gao-bin-cost) | Hierarchical reuse, layer-wise preload, asynchronous saving and scheduler hints | Preloading/overlap and multi-turn caching are established | Compare against a pipeline, not only serialized restore |
| [Strata, OSDI 2026](https://www.usenix.org/conference/osdi26/presentation/xie-zhiqiang) | Layout/I/O co-design and cache-aware scheduling address long-context I/O stalls and delay hits | Generic hierarchy and cache-aware batches are established | Tuned I/O sizes, delay-hit handling and overlap in both policies |
| [HCache, EuroSys 2025 author preprint](https://arxiv.org/abs/2410.05004) | Intermediate-activation restoration, complementary compute/I/O scheduling and chunk storage | Restored state representations differ | Compare matched quality/compatibility and account for saved-state bytes and compute |
| [Parrot, OSDI 2024](https://www.usenix.org/conference/osdi24/presentation/lin-chaofan) | Semantic variables expose application dataflow for end-to-end optimization | Workflow-aware serving is established | Same application-visible dependency interface |
| [KVFlow, 2025 preprint](https://arxiv.org/abs/2507.07400) | Agent-step graph and steps-to-execution guide eviction and prefetch | Workflow-guided normal KV reuse is established | Same ordinary prefix cache and fault-safe backing underneath |
| [TOPAS, 2026 preprint](https://arxiv.org/abs/2608.25523v1) | Joint prefix retention/execution combines longest remaining service path, reuse and movement | This is close prior work; “Slack + cache” is insufficient novelty | Add common-failure episodes and checkpoint migration to a matched substrate; remove each new term |
| [Pythia, 2026 preprint](https://arxiv.org/abs/2604.25899v2) | Workflow semantics reduce serving inefficiencies | Predictable Agent structure is established | Compare normal locality/load policies independently from fault protection |
| [Cortex, 2025 preprint](https://arxiv.org/abs/2510.14126) | Workflow-aware resource pooling and scheduling | Resource sharing and workflow scheduling are established | Hold pooling/serving scheduler fixed for placement attribution |
| [Landlord / On-Line File Caching](https://doi.org/10.1007/s00453-001-0124-5) | Online cost/size caching | Its competitive guarantee does not apply to a changing, non-additive joint-failure DAG objective | Direct revaluation vs rental with identical values, leases and migration limits |

The intended new claim is the combination of **common-failure workflow value, normal-reuse preservation, separate demotion/deletion values, and physically safe online tier transitions**. The prototype and strong-baseline experiments must demonstrate that this combination is necessary and useful. The current analytical artifact alone does not prove a systems contribution sufficient for EuroSys acceptance.
