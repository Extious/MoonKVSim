# 通用角色版 workflow 设计图

状态：**新提出的自建 DAG，尚未执行验证**。这里没有实验结果，也不把旧 7/8-Agent 的执行记录套用到新图。

本次用户要求减少角色种类、让角色面向一类通用任务，并绘制改进后的两类 workflow。两图均从左到右，每图 5 个 Agent 实例、3 种角色；每个节点是一个完整 Agent 任务，不是单次模型调用。字母标识实例，角色模板可以复用，实例之间的历史相互独立。边表示后继消费前驱产物，并等待所有前驱任务完成；就绪任务独立启动，不设置全局层级屏障。内部调用轮数由任务完成条件决定，尚未验证这些实例会自然产生多少轮或多少兼容 KV 前缀。

## 资料驱动的研究报告

- A/B 是两个研究员实例，各自负责预先指定的完整子问题，包含阅读、提取、比较、核查和形成证据结论；子问题随 job 输入改变，角色模板保持通用。
- C 是分析员实例，基于 A 的证据完成一个专题的深入分析。
- D 是另一个分析员实例，需要 A/B 两方面的证据，完成跨方面的联合评估。它与 C 的分析范围不同；不需要 C 的结论时，两者可并行。
- E 是报告作者，消费 C/D 的分析及其附带的完整来源索引，形成并修订报告。
- 依赖：A→C，A→D，B→D，C→E，D→E。A/B 并行；A 完成后 C 可以在 B 继续工作时启动；C/D 就绪后可以并行。

一个可理解的任务实例是“根据给定技术报告和实地评估材料，分析某项技术的可行性及采用条件”：A 研究技术证据，B 研究应用环境证据；C 分析技术论证的可靠性，D 综合技术证据与应用环境评估适用性；E 给出有引用和限制条件的报告。这是解释分工的例子，**不是采集过的真实 trace**，也不限定所有 job 必须是技术主题。

DeepResearchBench 可以作为真实问题来源，材料必须来自与问题相关的真实、带来源和时间范围的文档集合。这里的应用定位是给定资料上的研究与分析；本地检索耗时仍待实测，不宣称实现了完整在线 DeepResearch，不把事先采集的文档等同于在线搜索的实测时延。

## 软件问题调查、修复与验证

- A/B 是两个调查员实例：A 负责问题语义、实现和原因；B 负责现有测试、接口约束和复现/回归需求。
- C 是开发者，依据 A 的产物实施候选修改，并做必要的本地检查；无需等 B 完成就可以开始，前提是 B 的结果不是该修改必需的输入。
- D 是验证员实例，需要 B 的测试/约束分析和 C 的候选 patch，在真实环境中验证回归行为。
- E 是另一个验证员实例，消费 C 的完整 patch/来源说明和 D 的测试记录，对正确性、影响范围和未解决问题进行最终评审；评审通过与否由实际证据决定。
- 依赖：A→C，B→D，C→D，C→E，D→E。A/B 并行，C 可以与仍在运行的 B 重叠。C→E 是直接 patch 的产物依赖，即使它在执行顺序上可经 D 传递，评审员仍需读取原 patch。

SWE-bench Verified 可作为真实 issue 来源。实际执行必须建立对应 pre-fix 仓库与环境；官方 patch、test_patch 和答案不得提前输入 Agent。独立评测与 Agent 可见材料分开。该图是未来真实修复版的设计，旧 pilot 只生成分析/修改方案/未执行测试计划，未运行这个新图。实际测试可能耗时较长，因此不能预先宣称它满足短工具调用条件。如果特定 issue 的修复必须先消费 B 的结果，就需要修改依赖或改选适合该固定模板的任务，并记录选择规则。

## 文件与复现

- `workflows-zh.drawio`：中文可编辑源，两个页面。
- `workflows-en.drawio`：相同 DAG 的英文可编辑源，两个页面。
- `research-report-zh.png` / `software-issue-zh.png`：中文预览。
- `research-report-en.pdf` / `software-issue-en.pdf`：英文矢量图，168 mm 宽。
- `native/`：嵌入 Draw.io 源的 PDF/SVG/PNG；`review/`：最终尺寸的彩色/灰度预览和结构/字号检查。
- `workflow-contract.json`：本次设计的角色、实例、依赖、语义及证据状态。

生成：在此目录运行 `python3 build_and_render.py`。使用现有 Draw.io CLI 原生导出。延续项目的浅绿/浅蓝/浅橙、细灰色正交箭头和 Agent 字母标识。未修改主稿、serving 图、旧实验或旧 trace。

图形结构检查和最终尺寸的视觉检查只能验证图与设计一致、连线清晰、字可读；不能证明角色拆分的必要性、应用质量、典型性、短工具时延或 AegisKV 收益。这些需要新的实际执行与评价。
